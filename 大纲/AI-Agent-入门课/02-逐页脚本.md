- **时长**：50s
- **一句话论题**：AlphaGo、ChatGPT、会操作电脑的 Agent，是三次不同的跃迁。
- **屏幕文字**：2016 / 2022 / 2026；看 → 说 → 做
- **画面**：三联屏。左：围棋棋盘，最后一子落下；中：一个干净的聊天框，光标闪烁；右：一台笔记本电脑，鼠标自己移动，文件被打开、代码被修改。三联屏底部各放一个小 Logo：左 DeepMind、中 ChatGPT、右 OpenClaw / WorkBuddy / DSH。

- **旁白**：
  > 2016 年，一台机器在围棋上赢了李世石。6 年后，也就是 2022 年，一个聊天框让所有人第一次觉得，AI 什么都能聊。4 年后，2026 年，AI 不再只是回答你，它开始自己打开文件、写代码、跑命令。今天，我们要讲的就是 AI 的 10 年发展历程，以及如何把当前的 AI 用好。

- **屏幕文字**：2016.03 / 首尔 / AlphaGo 4:1 李世石 / DeepMind
- **画面**：棋盘俯视，黑白子逐渐填满；镜头推到一角，棋子变成发光的“棋形”；旁边浮出三个小标签：看、想、练；右下角放 DeepMind Logo，旁边是当年的现场照片。

- **旁白**：

## S04 · cnn — 一层一层的滤镜

- **时长**：90s
- **一句话论题**：CNN 不写规则，它从数据里学“特征”；它的工业拐点是 2012，不是 2016。
- **屏幕文字**：像素 → 边缘 → 形状 → 物体；2012 AlexNet；26.2% → 15.3%
- **画面**：左边一张真实猫照片（先像素化），右边四层“滤镜”依次抽出：第一层只有边缘，第二层有耳朵/胡须的轮廓，第三层有眼睛，第四层拼成一只猫。下方一条应用带：医疗影像、工业质检、人脸、OCR；讲到 AlphaGo 时，再贴上 AlphaGo 赢李世石和柯洁的两张照片，右下角带 DeepMind Logo。
- **动画**：像素图先马赛克化，再逐层“清晰”；每层滤镜用半透明色块扫过；应用带从右往左滑入。
- **旁白**：
  > 10 年前，AI 主要的能力是它“看”的本事，这个能力来自于卷积神经网络，CNN。你可以把它想成一层一层的滤镜：第一层看边缘，第二层看形状，第三层看眼睛、耳朵，最后拼成一只猫。以前我们写规则：“有尖耳朵、有胡须、有尾巴”，但真实世界太复杂，规则写不完。CNN 换了个办法：不写规则，给你看几百万张图，让它自己学特征。这件事的拐点其实不是 2016，是 2012 年。AlexNet 在 ImageNet 比赛上把 Top-5 错误率从 26.2% 降到 15.3%，从那以后，CNN 进了医院、工厂、手机和摄像头。AlphaGo 只是让大众更全面地了解到这个技术的能力。
- **事实/口径**：AlexNet 2012，ImageNet Top-5 错误率 26.2% → 15.3%；CNN 不是 AlphaGo 发明的。应用例子是示意，不声称“所有行业都用 CNN”。
- **素材**：猫图用 `./素材/photo/cat.jpg`（CC0，Wikimedia Commons，作者 AdinaVoicu）做像素化处理；滤镜层用 SVG + 半透明遮罩；应用图标用线性图标；`./素材/photo/alphago-lee-sedol.webp`、`./素材/photo/alphago-ke-jie.jpg`、`./素材/logo/deepmind.png`。

## S06 · scaling-emergence — 规模定律与涌现

- **时长**：210s
- **一句话论题**：任务没变，规模变了；能力不是慢慢长上去的，是在跨过某个门槛之后突然出现的。
- **屏幕文字**：2019 GPT-2 1.5B / 2020 GPT-3 175B；Scaling Law；Emergent Abilities；三位数加法 <10% → 80%；量变引起质变
- **画面**：一张主图贯穿整屏：横轴是模型规模（对数刻度：1.25 亿、3.5 亿、7.6 亿、13 亿、27 亿、67 亿、130 亿、1750 亿），纵轴是准确率。先出现一条平滑上升的曲线（规模定律）；然后画面切到“多位数加法”，曲线在 130 亿之前贴着地面，到 1750 亿突然竖起来，形成一个“台阶/悬崖”。台阶右侧打上“Emergent Abilities”标签。第三段插入一个小对比：左边 1.3B InstructGPT，右边 175B GPT-3，人类偏好投票小模型胜出。最后画面底部滑出一条细时间轴：2017 Transformer → 2018 BERT → 2020 GPT-3 → 2021 悟道 2.0 → 2023 文心一言/通义千问/ChatGLM → 2024–2025 DeepSeek/Kimi。
- **动画**：① 三根柱子从低到高（117M → 1.5B → 175B），背景曲线随柱子显现；② 曲线切换成加法准确率：前七个点依次落在贴近 0 的位置，最后一个点“弹”到 80%，伴随一次短促的镜头推近；③ 台阶定格，标签淡入；④ 投票条从左往右长，小模型那侧超过大模型；⑤ 底部时间轴从左往右生长，中国节点用另一种颜色。全程只用一个运动焦点，不要同时动。
- **分镜节拍**：

| 节拍 | 时间 | 画面 | 旁白落点 |
| --- | --- | --- | --- |
| 1 | 0–35s | GPT-2 生成一段很像人写的文字，旁边是“它能干活吗？”的问号 | 2019 年就有 GPT-2，为什么大家没感觉 |
| 2 | 35–75s | 三根柱子 + 平滑上升的规模曲线 | 任务没变，规模变了；规模定律是可预测的 |
| 3 | 75–125s | 多位数加法的“悬崖”图，13B 贴地、175B 跳起 | 能力不是线性增长，是涌现 |
| 4 | 125–170s | 1.3B InstructGPT vs 175B GPT-3 的人类偏好投票 | 规模之外，还有对齐 |
| 5 | 170–210s | 底部时间轴：Transformer/BERT/悟道/文心/通义/ChatGLM/DeepSeek/Kimi | 不是 OpenAI 一家的独角戏 |

- **旁白**：
  > 大语言模型不是 2022 年才发明的，学界研究了很多年。2019 年，OpenAI 放出 GPT-2，15 亿参数。它写出来的文字已经很像人了，但当时并没有引起太多的关注，因为他的能力还不够出众，无法满足我们日常的工作。2020 年，GPT-3 来了，1750 亿参数，任务还是同一个：猜下一个词。OpenAI 发现，模型越大、数据越多、算力越多，能力会按一条相当稳定的曲线往上走。这就是 scaling law，规模定律。直白的说就是“大力出奇迹”。
  >
  > 真正让人意外的，是另一件事。GPT-3 的论文里有一组多位数加法的实验：从 1.25 亿到 130 亿参数的模型，三位数加法基本都在 10% 以下，跟瞎猜差不多；可一跨过 130 亿这个门槛，到 1750 亿，准确率一下跳到 80%。两位数加法更明显：130 亿那一档只能对一半，1750 亿接近全对。不是慢慢变好，是在某个门槛上，突然就会了。2022 年，有研究把这个现象命名为“涌现能力”，Emergent Abilities：有些能力，在小模型上根本看不到，模型大到一定程度，它突然就出现了。用一句话说，就是量变引起质变。这也是为什么，GPT-2 时代大家没感觉，GPT-3 之后，很多人觉得：大语言模型的智商非常的高。
  >
  > 大语言模型不是 OpenAI 一家的独角戏。2017 年，谷歌的 Transformer 铺好了路；2018 年，BERT 证明了预训练的力量；2021 年，国内的悟道 2.0 进了万亿参数俱乐部；2023 年，文心一言、通义千问、ChatGLM 接连发布；后面还有 DeepSeek、Kimi。

- **事实/口径**：GPT-2 1.5B（2019-02）；GPT-3 175B（2020-05）；scaling law 论文 2020-01；GPT-3 论文 Figure 3.10：三位数加法，13B 及以下模型准确率低于 10%，175B 约 80.4%；两位数加法 13B 约一半、175B 接近满分。涌现能力论文 2022（Wei 等，arXiv:2206.07682），定义是“小模型没有、大模型出现的能力”；“涌现是海市蜃楼”论文 2023（arXiv:2304.15004）指出部分“突然”可能是评测指标造成的。InstructGPT 2022，1.3B 在人类偏好上优于 175B GPT-3，这是特定评测，不是“1.3B 全面强于 175B”。悟道 2.0 2021-06，1.75 万亿（稀疏）；文心一言 2023-03-16；通义千问 2023-04-11；ChatGLM-6B 2023-03-14；DeepSeek-V3 2024-12；Kimi K2 2025-07。不要展开 benchmark。
- **素材**：柱状图 + 曲线 + 台阶图（数据按 GPT-3 论文 Figure 3.10 重绘，不直接使用论文截图；重绘参考 `./素材/diagram/gpt3-arithmetic.png`、`./素材/diagram/gpt3-aggregate-performance.png`）；`./素材/logo/openai.png`；底部时间轴用文字标签，国内节点可配 `./素材/logo/qwen.png`、`./素材/logo/deepseek.png`、`./素材/logo/kimi.png`；数字用等宽字体。

## S07 · chatgpt — 一个只动嘴的顾问

- **时长**：70s

## S09 · l3-agent — 给 AI 套一层行动循环

- **时长**：70s
- **一句话论题**：补全是“猜下一行”，Agent 是“做一步、看结果、再决定下一步”。
- **屏幕文字**：2023.03 Cursor / 2024.11 Agent 模式 / ReAct / Function Calling
- **画面**：左边代码编辑器，光标补全一行；右边同一个编辑器，Agent 自己打开三个文件、改代码、跑测试、看到红色报错、再改；中间一个循环图：观察 → 思考 → 行动 → 观察。编辑器右上角放 Cursor Logo；讲到 Agent 模式时，旁边浮出 Cursor 真实界面截图。
- **动画**：左边只补一行；右边文件树依次展开，diff 逐行出现，测试窗口变红再变绿；循环图旋转，箭头流动；Cursor 截图在讲到“Agent 模式”时淡入，然后缩小到角落。
- **旁白**：
  > 第三阶段，变化发生在程序员这边。Cursor 最早只是代码补全，2023 年 3 月上线；到 2024 年 11 月，它有了 Agent 模式。区别在于，补全，是你写一行，它猜下一行；Agent，是你给它一个目标，它自己读文件、改代码、跑测试，看到报错再改。给 AI 套一层循环，它就从“工具”变成了“数字工人”。这个循环，学术界 2022 年就有个名字，叫 ReAct：推理、行动、观察，再推理。2023 年，OpenAI 又把 function calling 做成了标准接口。循环加工具，Agent 的大门就打开了。
- **事实/口径**：Cursor 2023-03-14 上线；Agent 模式 2024-11-24；ReAct 2022；OpenAI function calling 2023-06-13。
- **素材**：代码编辑器 mock、diff、测试窗口、循环图；`./素材/logo/cursor.png`、`./素材/screenshot/cursor-agent-mode.png`。

## S11 · two-generations — 两代智能体

## S12 · harness-anatomy — 一个完整能力的办公工位

- **时长**：85s
- **一句话论题**：Harness 的四件套是工具、Skill、MCP、行动循环；外面还有上下文和权限。
- **屏幕文字**：工具 = 办公设备 / Skill = 岗位 SOP / MCP = 跨部门接口 / 行动循环 = 工作闭环 / 权限 = 岗位权责
- **画面**：空办公工位 → 配齐设备的工位 → 连上公司系统 → 循环处理工单；桌面标出四个核心部件，外围标出“文件柜”和“权限牌”。
- **动画**：先出现空工位；摆上电脑、打印机、键盘（工具项依次亮起）；放上岗位 SOP 手册与流程图示（Skill 亮起）；工位系统同时连上财务、人事、业务系统（MCP 亮起，多系统连线）；“接需求 - 处理 - 交付 - 反馈”四步循环流动（行动循环亮起）；最后外围浮现历史档案柜和岗位权限牌。
- **旁白**：
  > 把 Harness 看成一个员工的工位。工具，是纸、笔、电脑、打印机、键盘这些设备，是员工干活的工具；Skill，是岗位 SOP 和作业手册，告诉他每件事的标准流程；MCP，是跨部门的系统接口，让他能和财务、业务所有体系打通协作；行动循环，就是“接需求 - 处理 - 交付 - 反馈”的工作闭环，是他持续运转的节奏。上下文是工作日志和档案，决定他“记得什么”；权限是岗位权责和审批等级，决定他“能碰什么”。四件加两层，就是 Harness 的完整组成。而真正办公的人，就是 Harness 对接的大脑；这个工位可以有不同智力的员工入座：聪明的员工相当于能力更强的模型，不聪明的员工相当于能力相对较弱的模型。他们都可以在这个工位里干活，干活的好坏，取决于员工的聪明程度，也就是模型的能力强弱。其实 harness 是一个工程学问题，目前各大厂家提供的工位能力都差不多，而决定 harness 强弱的是这个工作流程及工作准则
- **事实/口径**：这是教学比喻；Harness 的工程定义见 Microsoft Learn：“runtime scaffolding that turns a language model into an agent”。
- **素材**：工位 + 电脑 + 纸 + 笔 + 鼠标 + 键盘 + 档案手册（Skill） + 行为准则。

## S13 · tools-skills-mcp — 说到底，都是喂给模型的文字

- **时长**：100s
- **一句话论题**：工具、Skill、MCP 看着是三种能力，本质都是提前把一段文字注入给模型。
- **屏幕文字**：工具 = 固定格式 / Skill = 固定流程 / MCP = 统一接口；模型只能读文字
- **画面**：左边一个“模型”对话框；右边三个投喂口，每个口子往模型里送一段文字：
  1. 工具卡片：`write_file(path, content)` → `ok`，上面写着“固定格式、固定返回”；
  2. Skill 小册子：`SKILL.md`，封面写“这类活怎么做”，里面是步骤、注意事项、脚本；
  3. MCP 接口面板：外部软件（数据库、日历、画图软件）按同一个格式登记自己的能力，Agent 通过接口调用。
- **动画**：三张卡片依次飞进模型左侧的“上下文”入口；每飞入一张，模型右侧就多一个能力图标；最后三张卡片合在一起，变成一行字：“都是文字”。MCP 卡片上出现“接口”两个字，不出现 USB-C 之类的比喻。
- **旁白**：
  > 工具、Skill、MCP，名字不一样，但有一件事是一样的：它们最后都得变成一段文字，塞进模型的上下文里。因为模型只能读文字。工具，是一个固定格式：我告诉你，你可以调用 write_file，参数是路径和内容；你按这个格式说，我替你去执行，再把结果以文字还给你。Skill，是一段固定流程：把我做这类事的经验写成一份说明书，需要的时候整段喂进去，模型照着做。MCP，是一个统一的接口：外部软件按同一个格式，把自己的能力登记成工具说明书，Agent 就能接上它。你可以把它们理解成三种“提前写好的提示词”：工具是格式，Skill 是流程，MCP 是接口。所以 Harness 的能力边界，很多时候不取决于模型多聪明，而取决于你提前给它喂了什么。
- **事实/口径**：现代 API 用结构化的 `tool_calls`，不是让模型直接输出一段裸 JSON 文本，教学上简化为“固定格式的结构化意图”；Skill 常见格式是 `SKILL.md` + YAML frontmatter（name/description），可带脚本/资源；MCP 是开放协议（JSON-RPC），服务器可暴露 tools/resources/prompts；工具结果、Skill 内容、MCP 工具描述最终都以文本形式进入上下文。不要把 MCP 说成 Skill，也不要用 USB-C 比喻。
- **素材**：自绘卡片、上下文入口、接口面板；`./素材/logo/mcp.png`（若可用）；代码/文件名用等宽字体。

  > DeepSeek也开发了自己的Agent, DeepSeek Harness。它 2026 年 8 月发布 v0.1，9 月底出桌面端，11 月初日活 154 万。它最特别的地方不是模型，是架构：基于 Cordis 插件运行时，模型、工具、Skill、会话、沙箱、Agent Loop，全都是插件。连“循环”本身都可以被替换。这意味着，你可以让 Harness 改变自己的功能，这是一种全新的软件设计范畴。软件的界面想要怎样，是由你说了算，而不是官方给你设计好你就继续这样用，你完全可以让它自己改成你想要的样子。它是一套可以自己生长的 Harness。

# 第五幕 · 如何用好 Agent

## S17 · stateless-notebook — 黑屋专家，只认笔记本

- **时长**：145s
- **一句话论题**：大模型 API 默认无状态；记忆不在模型里，在 Harness 用上下文拼出来的那本笔记本里。
- **屏幕文字**：无状态 / 笔记本 / 每次从第一页读 / 上下文窗口 / 记忆在 Harness
- **画面**：一间黑屋。屋子很小：一张桌子、一盏暖灯、一个黄铜传递窗；专家坐在桌后，只露剪影，不露脸；门外是一条长队，每个人手里一本牛皮纸封面的笔记本。每本笔记本：第一页是“系统提示词”（像一张工牌/SOP），后面是问题、回答、工具结果（贴着便签），最后一页是这次要回答的问题。专家从第一页读到最后一页，在下一页写答案，合上，递出去；下一个本子进来，他又从头开始。
- **动画**：先出三个“它还记得”的小窗口（换模型/断网/第二天），再切黑屋；笔记本从窗口飞入，页码快速翻动，专家写字，笔记本飞回；队伍变长；镜头推到笔记本内部，看见系统提示、对话、工具便签；最后出现一把“厚度尺”卡在窗口上，超过厚度的页被折起/压缩成摘要；收尾切到 DSH 桌面端截图，能看见上下文被拼出来的过程。
- **分镜节拍**：

| 节拍 | 时间 | 画面 | 旁白落点 |
| --- | --- | --- | --- |
| 1 | 0–20s | 三个小窗口：换模型还在、断网还在、第二天还在 | 记忆到底存在哪 |
| 2 | 20–40s | 黑屋、暖灯、传递窗、专家剪影、门外长队 | 专家不认人，只认笔记本 |
| 3 | 40–75s | 一本笔记本的结构：系统提示、对话、工具便签、问题 | 每次从第一页读到最后一页 |
| 4 | 75–100s | 换模型/断网/长对话三张小图 | 三个现象，一本笔记本就能解释 |
| 5 | 100–125s | 窗口上的“厚度尺”，超出的页被压缩 | 上下文窗口是有限的 |
| 6 | 125–145s | DSH 界面：系统提示 + 历史 + 工具结果拼成一次请求 | 记忆在 Harness，不在模型 |

- **视觉细节（美术参考）**：
  - 色调：黑屋用深底 #0B0B0C + 2700K 暖黄吊灯；笔记本是牛皮纸暖棕；工具结果用淡黄便签；系统提示词那页盖一个蓝色“系统”印章。
  - 专家：只画手、袖口和剪影，不画脸；五个动作要慢：翻页、压纸、写字、合本、推回，每个 0.6–0.8 秒。
  - 传递窗：黄铜边框 + 毛玻璃；窗口上方一把刻度尺，表示上下文窗口的厚度；超出的页被折角、用绳子捆住，表示压缩。
  - 队列：门外的人只有剪影，每人一本笔记本，队伍延伸到画面外；镜头不要拍脸。
  - 声音：翻页声、盖章声、远处队伍的低语；不要配乐。
  - 收尾：从黑屋切到 DSH 桌面端截图，用框线标出“系统提示 / 历史消息 / 工具结果”，再回到黑屋定格。

- **旁白**：
  > 先问一个你肯定遇到过的问题：你换一个模型，对话还能接着聊；网断了重连，记录还在；第二天打开，它还记得昨天聊到哪。可大模型的 API，默认是“不记得你”的。那这些记忆，到底存在哪？
  >
  > 你可以把大模型想成一个黑屋里的专家。屋子很小，只有一张桌子、一盏灯、一个窗口。专家非常聪明，但他不认人，只认笔记本。门外排着成千上万的人，每人手里一本笔记本。
  >
  > 每一本笔记本，就是一次会话。第一页是 Harness 写的系统提示词：你是谁、能做什么、不能做什么。后面是你们聊过的每一句话，中间还夹着工具返回的结果。专家每次拿到本子，都从第一页开始读，一直读到最后一页，然后在下一页写下答案，合上，递出去。下一个本子进来，他又是从头开始。
  >
  > 现在你就能解释那三件事了。换模型，就是把同一本笔记本，递给另一个专家；断网，就是笔记本一直在你手里，重新递进去就行；那为什么长对话越来越贵？因为每问一次，专家都要把整本从头读一遍。而且这个窗口一次能塞进去的厚度是有限的，这就是上下文窗口。本子太厚，前面的内容就得压缩、丢掉。所以真正的记忆不在模型里，在 Harness 帮你整理的这本笔记本里。
  >

- **事实/口径**：API 默认无状态；但产品层可以存会话（ChatGPT 网页、Responses `store` 等）。旁白说“API 默认”，留了口子；不要绝对说“所有大模型都不存会话”。上下文窗口有上限，Harness 常用压缩/摘要把长会话塞进窗口，压缩会丢细节。
- **素材**：黑屋、专家剪影、笔记本、传递窗、队伍、厚度尺；暖灯 + 深色背景；`./素材/screenshot/dsh-desktop.png`（真实 DSH 轨迹界面，官方产品页合成图，裁出中间窗口使用）。

## S18 · long-session — 长会话不是免费的记忆

- **时长**：100s
- **一句话论题**：每轮都要把整本上下文重放一遍，token 越滚越多，长会话越聊越贵；所以一任务，一会话。
- **屏幕文字**：第 20 轮 = 前 19 轮全量重放；token 越滚越多；一任务，一会话
- **画面**：一本笔记本越来越厚；每翻一页，旁边一个 token 计数器往上跳；最后出现一条“累计 token”曲线。镜头拉远，桌上多出一本干净的新笔记本，旧本子被推到一边，新本子第一页写着这次任务的名字。
- **动画**：笔记本逐页变厚；计数器数字快速上涨；曲线从线性变成上翘；定格在一个具体数字例子；新本子滑入画面，五张“什么时候该新开”的小卡片依次翻开，最后收拢成一句话“一任务，一会话”。
- **旁白**：
  > 但代价也在这里：你聊到第 20 轮，第 20 次请求带的，是前 19 轮的全部内容——每答一次，专家都要从头读一遍。所以长会话不是“免费的记忆”，而是“每一轮都重新买一遍”。这就是为什么，很多人问一个小问题，还挂在原来的长会话里，token 会烧得很快。
  >
  > 所以，第一个使用习惯：一任务，一会话。新任务，新会话；旧上下文和新问题无关，新会话；会话太长、或者上下文窗口快满了，先总结再新开；换模型、换供应商，想干净一点就新开；舍不得丢的结论，让 Agent 先写一份 handoff，再新开。一句话：一任务，一会话。可有些任务天生就长，中途没法换本子，那本子写满了怎么办？
- **事实/口径**：实际计费还涉及系统提示、工具 schema、检索内容、缓存等；这里只讲“全量重放”的主因。数字例子：每轮新增 500 token，20 轮累计约 10.5 万 token。新开会话是经验规则，不是硬性标准；不同 Harness 的上下文管理/压缩策略不同。
- **素材**：笔记本、token 计数器、曲线、五张卡片、handoff 模板。

## S19 · compact — 写满的笔记本，压成一页纸

- **时长**：105s
- **一句话论题**：上下文窗口是有限的；快写满时，Agent 会把整本笔记本压成一页纸，贴进一本新本子。
- **屏幕文字**：上下文窗口 / 快写满了 / Agent 自己压缩 / 一页纸 / 会丢信息
- **画面**：还是 S17 那间黑屋。桌上的笔记本已经厚到合不上；专家翻到一半，手停下来，灯光也像暗了一格——他的精力和记忆是有限的，超出这个厚度的页，他读不完，也记不住。窗口上方的“厚度尺”爆表，超出的页被挡在窗口外面。这时画面里伸出一只手（Agent 的手）：把旧本子摊开，在全新的一页纸上写下几句“这个本子讲了什么”，撕下这一页，贴进一本刚拆封的新笔记本，只占第一页。新本子从传递窗递进去，专家很快读完，继续写答案。旧本子合上，放进旁边的档案柜，不销毁。
- **动画**：笔记本逐页加厚 → 厚度尺超过刻度、亮红 → 专家翻页变慢、停在中间 → 一页摘要从旧本子里“长”出来（文字逐行提炼）→ 摘要粘进新本子 → 新本子递进窗口 → 专家快速翻完、落笔 → 最后一行小字：“压缩由 Agent 自动触发”。
- **分镜节拍**：

| 节拍 | 时间 | 画面 | 旁白落点 |
| --- | --- | --- | --- |
| 1 | 0–25s | 厚到合不上的笔记本，专家越翻越慢 | 专家的精力、记忆都是有限的 |
| 2 | 25–50s | 厚度尺爆表，超出的页读不进去 | 超出窗口的部分，专家根本读不到 |
| 3 | 50–75s | Agent 把整本提炼成一页，贴进新本子 | 这就是上下文压缩 |
| 4 | 75–105s | 新旧两本对照，一些句子在摘要里消失 | 压缩由模型自己判断，重要的信息也可能丢 |

- **旁白**：
  > 但笔记本迟早会写满，因为现在大模型的上下文窗口是有限的。你想想专家的处境：他每一次都要从第一页读到最后一页；本子越厚，他读得越慢，忘得也越多。他的精力和记忆都有上限——一旦本子厚过这个上限，后面的页他就读不到，更谈不上理解。
  >
  > 这时候，Agent 会自己动手：把整本笔记本摊开，用一页纸，把这个本子里最核心的论点写下来——做过什么、定了什么、还剩什么没做完；然后把这一页贴进一本全新的笔记本，当作新的材料，再递进去。这就是上下文压缩，compaction。新本子很薄，专家一眼读完，又能继续干活。
  >
  > 但你要知道代价：这一页纸是模型自己总结的。它认为不重要的一句话，可能恰恰是你最在意的——某条规矩、某个数字、某句“这个目录不要动”，都可能在压缩时被抹掉。压缩能救急，不能当记忆用；真正不能丢的东西，要写进你自己能控制的地方。
- **事实/口径**：上下文窗口有上限；上下文压缩（compaction / auto-compact）通常由 Harness 在接近窗口上限时自动触发，把历史摘要成更短的上下文再继续对话；不同产品的触发阈值、摘要方式不同；摘要由模型生成，会丢细节，不保证保留人认为关键的信息。不要说成“模型记住了”。
- **素材**：回收 S17 的黑屋、专家、传递窗；更厚的笔记本；一页摘要；全新的笔记本；厚度尺；档案柜；可选 `./素材/screenshot/dsh-desktop.png`（标出上下文拼接/压缩的位置）。

## S20 · agents-md — 给 AI 一个项目记忆

- **时长**：95s
- **一句话论题**：项目的事写进工作区的 agents.md，个人的习惯写进全局记忆；AI 每次开工前先读它。
- **屏幕文字**：AGENTS.md / 项目记忆 / 全局记忆 / 约定俗成
- **画面**：三栏递进。
  - 左：新会话窗口，用户又在打一段很长的项目背景：“这个项目是……我们的目标是……不要动 xxx 目录……”；旁边堆起一摞写满同样内容的纸，越堆越高。
  - 中：工作区根目录出现一个 `AGENTS.md` 文件，像一本“项目手册”立在门口；AI 推门进来，先拿起手册读；之后每开一个新会话，手册自动被带上，纸堆消失；画面一角可嵌入 `agents.md` 官网截图（“60k+ open-source projects”“One AGENTS.md works across many agents”），作为“约定俗成”的证据。
  - 右：全局记忆。两栏对比：项目级（`AGENTS.md`：项目背景、目标、目录结构、常用命令、禁止事项）和全局级（`~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`、`memory.md`：永远用中文回答、不要自动 commit 这类个人习惯）。
- **动画**：重复解释的纸越堆越高 → `AGENTS.md` 出现，纸堆被吸进文件 → AI 进门先读手册 → 镜头拉到全局层，全局文件亮起 → 最后两栏并排，中间一条线，左边写“项目”，右边写“习惯”。
- **旁白**：
  > 还有一件很烦的事：每开一个新会话，你都要重新解释一遍——这个项目是干什么的、最终要做什么、哪些目录不能动。说一遍两遍还行，说十遍就受不了了。办法其实很简单：在工作区根目录放一个 agents.md。它已经是一个约定俗成的文件，Codex、Cursor、OpenCode 这些工具都认它；Claude Code 的 CLAUDE.md，也是同一个道理。你把项目背景、目标、目录结构、常用命令，还有“禁止做什么”写进去；AI 每次开工之前，会先读它。这相当于给 AI 一个项目记忆。
  >
  > 还有一些 Agent 支持全局记忆：比如 Claude Code 的 `~/.claude/CLAUDE.md`，Codex 的 `~/.codex/AGENTS.md`，或者有些工具里的 memory.md。像“永远用中文回答”“不要自动 commit”这种跨项目都成立的偏好，就写在全局里。项目的事写项目里，个人的习惯写全局里。
- **事实/口径**：AGENTS.md 是开放格式，由 Agentic AI Foundation（Linux Foundation）托管；Codex、Cursor、OpenCode、Gemini CLI、Windsurf、Devin 等工具支持；放在仓库根目录，子目录可以放嵌套的 AGENTS.md，最近的优先。Claude Code 默认读 `CLAUDE.md`（项目级）和 `~/.claude/CLAUDE.md`（用户级），也可以通过导入/配置兼容 AGENTS.md；Codex 的项目级是 `AGENTS.md`，用户级是 `~/.codex/AGENTS.md`。DSH 也读 `AGENTS.md`；开箱只记住一个会话内的事，跨会话长期记忆需要记忆插件。不要把“agents.md”写成某个工具专属。
- **素材**：自绘：新会话窗口、纸堆、`AGENTS.md` 手册、门、两栏对比；文件路径用等宽字体；可用本仓库真实的 `AGENTS.md` 片段做画面内容（节选“不可协商”两三条）；`./素材/screenshot/agents-md-site.png`（agents.md 官网截图，自截）。

## S21 · safety — 能操作电脑，不等于可以随便操作

- **时长**：70s
- **一句话论题**：Agent 的能力和风险是同一件事；权限、沙箱、审批是必修。
- **屏幕文字**：提示注入 / 权限 / 沙箱 / 审批；OpenClaw 2026.03 安全预警
- **画面**：一封邮件里藏着一行小字“忽略之前的指令”；模型看到这行字，伸手去拿“删除文件”按钮；一道权限门挡住；门旁边有三个开关：目录、命令、网络；最后出现“人工审批”印章；讲到审批时，在权限门旁嵌入 Claude Code 真实权限弹窗截图（“This command requires approval”）。讲到 OpenClaw 时，右上角放 OpenClaw Logo。
- **动画**：邮件展开，小字高亮；模型的手伸向按钮；权限门“砰”地关上；三个开关依次拨动；印章盖下。
- **旁白**：
  > 最后，必须讲安全。Agent 能操作电脑，这是它的能力，也是它的风险。第一，提示注入：网页、文件、邮件里的一句话，可能骗它“忽略之前的指令”。第二，权限：它默认能碰什么？目录、命令、网络、账号，都要设边界。第三，审批：高风险动作，必须有人点确认。2026 年 3 月，OpenClaw 就因为默认配置、插件生态、行为管控等问题，被国内多个安全机构预警。能操作电脑，不等于可以随便操作。
- **事实/口径**：2026-03 国家网络与信息安全信息通报中心、工信部 NVDB、国家互联网应急中心等发布 OpenClaw 安全风险提示/预警；具体措辞见来源。不要制造恐慌，强调“权限/沙箱/审批”。
- **素材**：邮件、权限门、三个开关、审批印章；警示色用珊瑚红；`./素材/logo/openclaw.png`；`./素材/screenshot/claude-code-permission.png`（Claude Code 官方权限弹窗截图）。

## S22 · closing — 第三次跃迁

- **时长**：60s
- **一句话论题**：AI 学会看、说、做；接下来轮到我们学会怎么用。
- **屏幕文字**：看 / 说 / 做 → 用；三个行动
- **画面**：三个词依次亮起，最后一个是“用”；然后三张行动卡片：真实任务跑一周 / 一任务一会话，给项目写一份 agents.md / 读一遍工具配置；最后画面回到开头的三联屏，但这次三块画面连成一条上升的线，三联屏底部还是那三个 Logo。
- **动画**：三个词亮起；“用”放大；三张卡片依次翻出；三联屏重新出现，连线上升；最后定格在一句话。
- **旁白**：
  > 回到开头。AI 学会看，是 AlphaGo 和 CNN；学会说，是 GPT 和 ChatGPT；学会做，是 Agent 和 Harness。如果你当前还是仅仅只会使用对话型的大模型，那么建议你还是下载一个真正的 Agent 工具体验一下，让它帮你做个 PPT，帮你处理一下数据，帮你搭建一个平台或者软件，甚至你可以让他给你做一个游戏。AI 的第三次跃迁，才刚刚开始。很难预估未来1~2年还会发生什么样的变革，可以大家一起期待一下。
- **事实/口径**：结尾是观点/行动建议，不是事实断言。
- **素材**：三联屏回收、三张行动卡片、上升线；`./素材/logo/deepmind.png`、`./素材/logo/chatgpt.png`、`./素材/logo/dsh.png`。

### 语速与停顿

- 旁白按 3.2–3.5 字/秒设计；如果主讲语速偏快，可把每屏时长缩短 10%。

- 每幕结束时，留 0.5 秒黑场/空镜，给观众换气。

- 一屏最多两个文字层级：标题 + 一句结论。

- 不在屏幕上放论文名、arXiv 编号、完整产品参数；这些放讲义。
