2. 用自己的话解释“参数量”，并知道参数多不等于聪明。
3. 说出 Agent 的三个阶段，以及“提示词型智能体”和“Harness 型智能体”的区别。
4. 理解“大模型 API 默认无状态、Harness 每次重放上下文”，并据此决定何时新开会话。
5. 说出 Harness 的四大件：工具、Skill、MCP、行动循环。
6. 知道“能操作电脑”背后的权限与安全边界。

## 这个大纲解决了什么

你的原始口述里，已经有很好的故事线和一个非常关键的洞察：**第二代智能体不是“更会写提示词”，而是“把模型装进一套工程系统里”**。这份大纲保留了这个洞察，并做了四件事：

1. **把“看”和“说”拆开**：AlphaGo 是专用感知系统，ChatGPT 是通用语言模型，不能混成一条线。
2. **把“参数量”讲成人话**：用旋钮墙、参数对比和“1.3B 也能赢 175B”的例子，避免“参数越多越聪明”的误解。
3. **把 Agent 分成三个阶段**：聊天框 → 工作流 → 循环式 Agent；再把第二代智能体分成“提示词型”和“Harness 型”。
4. **把使用心法落到一个比喻**：黑屋专家 + 笔记本。用这一个比喻，讲清换模型、断网、长对话贵、何时新开会话。

## 使用建议

- **第一次讲**：先读 `01` 和 `03`，再按 `02` 排练。`03` 里标了哪些话必须改、哪些可以保留。
- **做动画**：先做 `02` 的 S01–S04，跑通 `check` / `snapshot`，再批量做后面的镜头。
- **做课程**：按 `05` 的 9 集拆分，每集 6–10 屏。长版镜头是“叙事段”，课程版屏幕是“教学节拍”，不要把 80 秒镜头直接塞进一屏。
- **事实口径**：以 `03` 为准；`02` 里的旁白已经按修正后的口径写，不需要再改。
- **产品名**：统一用 `03` 的名称表；原稿里的“Code Cloud”“Coder Trace”“绘画”等，都是语音转写误差。
