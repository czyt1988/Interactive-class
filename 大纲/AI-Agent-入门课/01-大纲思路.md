# 大纲思路

## 0. 先给结论

这场演讲不是“AI 历史课”，而是“能力跃迁课”。

四个动词：**看、说、做、用**。

上半场解释 AI 怎么获得“看”和“说”的能力；下半场解释它怎么获得“做”的能力，以及我们怎么安全地用它。历史只负责提供路标，真正的主线是：**AI 从描述世界，走到了改变世界。**

---

## 1. 受众与目标

### 谁在听

- 用过 ChatGPT，但没写过代码的普通职场人。
- 听说过“智能体”“大模型”，但分不清 Agent、Harness、MCP、Skill 的人。
- 想用 AI 帮自己干活，但被“提示词课”和“产品广告”弄晕的人。
- 少量技术人员，希望把团队带进 Agent 工作流。

### 他们已经知道什么

- ChatGPT 能聊天、能写东西。
- AI 能生成图片、能写代码。
- 新闻里天天说“Agent”“大模型”“AGI”。

### 他们不知道什么

- AlphaGo 和 ChatGPT 不是一条技术路线。
- “参数量”到底是什么，为什么参数多不等于聪明。
- Agent 和聊天框、工作流到底差在哪。
- 为什么换模型、断网重连，对话还能继续。
- 为什么长对话很贵，什么时候该新开会话。
- 工具、Skill、MCP 分别是什么，为什么不是一回事。

### 他们最怕什么

- 听不懂术语。
- 被“技术神话”忽悠。
- 把 AI 放进电脑，结果它乱删文件。
- 学了一堆“提示词技巧”，回到工作里还是不会用。

### 三个设计约束

1. **不要求数学**：不讲反向传播、注意力公式、梯度。
2. **不要求编程**：可以用 JSON、终端、文件路径做例子，但不要求观众会写代码。
3. **不牺牲准确性**：比喻可以简化，但不能把错的说成对的；不确定的地方标出来。

所以，每一个技术概念都必须有一个“身体化”的比喻；每一个历史节点都必须服务一个论点。没有论点的年份，删掉。

## 2. 为什么是“看 → 说 → 做 → 用”

### 四个动词，四次跃迁

| 动词 | 技术范式 | 代表 | 观众能记住的画面 |
| --- | --- | --- | --- |
| 看 | CNN / 感知 | AlphaGo、AlexNet | 棋盘、滤镜、猫 |
| 说 | LLM / 生成 | GPT、ChatGPT | 聊天框、文字接龙 |
| 做 | Agent / 行动 | Cursor、Claude Code、OpenClaw | 循环、终端、自己动的鼠标 |
| 用 | Harness / 工程 | 协议、上下文、工具、Skill、MCP | 黑屋专家、笔记本、USB-C |

### 为什么不是按年份讲

按年份讲，观众记住的是一串“2016、2017、2018、2020、2022、2023、2025、2026”，然后全部忘掉。按动词讲，观众只需要记住四个字。四个字能复述，年份不能。

### 为什么不是按论文讲

论文是“技术内部视角”，新手要的是“能力外部视角”。Transformer、BERT、RLHF 这些词会出现，但只作为“发动机”的标签，不展开公式。

### 每个动词都有一个“极限”，极限推动下一幕

- **看** 的极限：不会说。CNN 能认出猫，但不能告诉你“这只猫在想什么”。
- **说** 的极限：不会做。ChatGPT 能告诉你“怎么改文件”，但不能替你改。
- **做** 的极限：不会管。Agent 能动手，但权限、上下文、成本、安全全是坑。
- **用** 的入口：理解协议与工程，才能不被产品宣传牵着走。

这个“极限推动下一幕”的结构，比“然后……然后……然后……”更紧，也更容易让观众产生“所以下一步必然是这样”的感觉。

## 3. 两幕结构：先来路，再用法

### 上半场：AI 从哪里来（约 12 分钟）

- 第一幕：看（AlphaGo / CNN）
- 第二幕：说（GPT / ChatGPT / 大语言模型）
- 中场转折：LLM 的极限（只会说，不会做）

### 下半场：AI 怎么干活、我们怎么用（约 22 分钟）

- 第三幕：做（Agent 三级跳 / 两代智能体 / Harness 解剖）
- 第四幕：群雄（Cursor / Claude Code / Codex / OpenCode / 国产 Harness / DSH）
- 第五幕：用（协议 / 无状态 / 成本 / 新开会话 / 工具 / Skill / MCP / 安全）

### 为什么在中场放“LLM 的极限”

如果上半场讲完 ChatGPT 就直接讲 Agent，观众会觉得“Agent 是另一个产品”。必须先让观众感到“ChatGPT 缺了点什么”——缺手、缺持久记忆、缺真正的会话——第三幕的 Agent 才会显得是“同一件事的下一步”，而不是“新出一个东西”。

这也是整场的情绪转折：从“AI 好厉害”，转到“AI 还差一步”，再转到“这一步已经发生了”。

## 4. 第一幕：AlphaGo 与 CNN

### 原稿的叙事方向是对的

你用 AlphaGo 开场，是对的。它有戏剧性、有具体比分、有“人类直觉最后堡垒”的冲突，比“2012 年 ImageNet 比赛”更适合开场。

### 但需要三个校正

1. **不是“谷歌总部”的 AlphaGo，是“谷歌旗下 DeepMind”的 AlphaGo。** 谷歌 2014 年收购 DeepMind，AlphaGo 是 DeepMind 的团队做的。讲“谷歌旗下”可以，但别把功劳全算给谷歌总部。
2. **AlphaGo 不是“纯 CNN”。** 它用了 CNN 策略网络和价值网络，加上蒙特卡洛树搜索（MCTS），再加上监督学习和强化学习。CNN 是“看棋形”的部分，不是全部。讲的时候可以说“它用 CNN 看棋形，用搜索想几步，用自我对弈练自己”。
3. **CNN 的工业拐点是 2012 年，不是 2016 年。** 2012 年 AlexNet 在 ImageNet 上把 Top-5 错误率从 26.2% 降到 15.3%，从那以后 CNN 进了医疗、工厂、手机、摄像头。AlphaGo 是“大众认知拐点”，不是“技术起点”。

### 为什么仍然从 AlphaGo 开场

因为观众需要“一个人”和“一个时刻”。李世石、4 比 1、首尔、2016 年 3 月，这些具体信息能让观众进入故事。AlexNet 更适合作为“技术拐点”的注脚，放在 CNN 那一屏。

### 讲完 CNN 就停

不要滑进反向传播、卷积核、池化、激活函数。新手只需要两个认知：

- CNN 是“一层一层的滤镜”：像素 → 边缘 → 形状 → 物体。
- CNN 是“学特征”，不是“写规则”：以前我们写“有尖耳朵、有胡须”，现在给它看几百万张图，让它自己学。

这两个认知，足够支撑“AI 学会了看”这句话。

## 5. 第二幕：LLM 的三台发动机

### 三台发动机

| 发动机 | 关键词 | 代表 | 给观众的一句话 |
| --- | --- | --- | --- |
| 架构 | Transformer | 2017 | 一种更适合“并行读一大段文字”的网络结构 |
| 规模 | 参数 / 数据 / 算力 | GPT-1 → GPT-2 → GPT-3 | 同样的“猜下一个词”，规模放大，能力变了 |
| 对齐 | 指令微调 / RLHF | InstructGPT、ChatGPT | 不只是“会做题”，还要“会跟人说话” |

### 为什么把“参数量”放在 ChatGPT 之前

因为观众需要一个“脑容量”的直觉，然后立刻打破它。

- 先给直觉：参数像一堵墙上的旋钮，训练就是调旋钮。
- 再给对比：GPT-1 1.17 亿 → GPT-2 15 亿 → GPT-3 1750 亿。
- 再打破：参数多不等于聪明；GPT-4 没公开；DeepSeek-V3 是 6710 亿总参数、370 亿激活；InstructGPT 1.3B 在人类偏好上赢过 GPT-3 175B。

这个“先建立、再打破”的顺序，比一上来就说“参数不重要”更有效。观众先有一个具体画面，再看到反例，才会真正记住。

### 为什么用“1.3B 胜过 175B”

这是一个反直觉的事实，能一击打破“参数决定论”。

但要注意口径：这不是说“1.3B 比 175B 强”，而是在**人类偏好**这项评测上，经过 RLHF 的 1.3B InstructGPT 更讨人喜欢。它说明“会跟人说话”是一种独立的能力，不是参数量的自动产物。

### 为什么讲中国团队

三个原因：

1. 避免“AI = OpenAI”的单一叙事。
2. 让国内观众知道，大模型不是舶来品的独角戏。
3. 为第四幕的国产 Harness 做铺垫：模型层有积累，工程层才不会从零开始。

但不要变成“国产模型发布会”。只讲三个节点：2021 年悟道 2.0（1.75 万亿参数）、2023 年文心一言/通义千问/ChatGLM、2024–2025 年 DeepSeek/Kimi。每个节点一句话，不展开 benchmark。

### 为什么给“涌现”加一个问号

新手最容易把“涌现”理解成“魔法时刻”：参数一到，AI 突然开窍。

更准确的讲法是：

- 规模定律是真的：模型越大、数据越多、算力越多，能力会稳定提升。
- 很多能力确实在跨过某个阈值后“看起来”突然出现，这叫涌现。
- 但学界有争论：有些“突然”，可能是因为我们用了非线性的评测指标；换个指标，就变成平滑上升。
- 所以，不是“参数一到就开窍”，而是“参数、数据、算力、对齐，四件事一起跨过阈值”。

这个问号很重要。它让观众知道科学是活的，不是“参数拜物教”。

### 结尾必须落到“LLM 的极限”

第三幕的入口，不是“Agent 很火”，而是“LLM 缺了什么”：

- 没有手：只能输出文字，不能改变外部状态。
- 没有持久记忆：每次请求都是新的，记忆靠 Harness 拼。
- 没有真正的会话：API 默认无状态，会话是产品层/工程层造的。

这三句话，直接引出 Harness。

## 6. 第三幕：Agent 的三级跳

### L1 聊天：人是循环

你问，它答；你再问，它再答。人是那个“循环控制器”。AI 是顾问，不是执行者。

### L2 工作流：人画图，AI 当齿轮

Coze（扣子）、Dify、n8n 这类工具，把流程画成一张图：识别意图 → 查知识库 → 回复 → 转人工。AI 是流水线上的一个节点。它很可靠，但路线是人定死的：图没画到的地方，它不会去。

智能客服是这一阶段的典型场景。

### L3 循环：AI 自己观察、行动、再观察

Cursor 是门口的标志。2023 年 3 月，它只是一个更好用的 AI IDE，核心是补全；2024 年 11 月，Agent 模式上线，它开始自己读文件、改多个文件、跑命令、看报错、再改。

“给 AI 套一层循环”，它就从“工具”变成了“工人”。

这个循环，学术界 2022 年就有名字：ReAct（推理 → 行动 → 观察 → 再推理）。2023 年，OpenAI 把 function calling 做成标准接口。循环 + 工具，Agent 的门就开了。

### 为什么把 Cursor 放在 L3 的门口

因为观众最容易共鸣“补全 → Agent”的转变：昨天它还在猜下一行，今天它已经会自己改一个项目。这个转变是可见的、可感的，不需要解释“什么是自主性”。

### 两代智能体：提示词型 vs Harness 型

| 维度 | 提示词型 | Harness 型 |
| --- | --- | --- |
| 核心 | 人设 + 知识 + 少量工具 | 行动循环 + 工具 + 上下文 + 权限 + 沙箱 |
| 能力 | 在预设范围内回答/执行 | 能在环境里闭环地改变状态 |
| 天花板 | 低：没有闭环，遇到错误不会自己修 | 高：能试错、能恢复、能长任务 |
| 典型 | 很多“我做了 100 个智能体” | Claude Code、Codex、Cursor、OpenClaw、DSH |

这个二分法是简化，但对外行非常有效。讲的时候要加一句：“不是提示词型没用，而是它和 Harness 型不是同一个物种。”

### 为什么用“马具”而不是“脚手架”

“脚手架”是临时的、外面的；“挽具”是把力量传导到车上的。

- 模型是马：有力气，但不知道该拉什么。
- Harness 是挽具：把模型的力量接到工具/任务上。
- 工具是车：真正改变世界的东西。
- 权限是缰绳：决定马能跑多远、能进哪块地。

这个比喻能自然带出“模型 / Harness / 工具 / 权限”四层，不需要额外解释。

### 为什么加“时间线/地图”

因为观众会问：“这么多产品，到底谁是谁？”

一条时间线（2023 AutoGPT → 2024 Devin/Cursor Agent → 2025 Claude Code/Codex → 2026 OpenClaw/WorkBuddy/DSH）加一张地图（国际/国内/DSH），能让观众知道这不是一个产品，而是一个物种。

同时要纠正一个常见说法：“2025 年中之后才流行”指的是“真正好用、真正出圈”，不是“概念第一次出现”。AutoGPT 2023 年就火了，Cursor 2023 年就有了，Devin 2024 年就出现了。概念的诞生和产品的可用，是两条曲线。

## 7. 第四幕：群雄

### 先地图，后产品

如果一上来就讲 Claude Code、Codex、Cursor、Kimi Code、Qwen Code、ZCode、Trae……观众会晕。先用一张地图分三类：

- 国际：Claude Code、Codex、Cursor、OpenCode。
- 国内：Kimi Code、Qwen Code、ZCode、Trae、CodeBuddy。
- 特殊样本：DeepSeek Harness。

再挑三个故事讲：Cursor（补全 → Agent）、Claude Code/Codex（2025 两个标杆）、DSH（插件化）。

### 为什么把 Cursor 单独讲

因为它是“补全 → Agent”的最佳案例，而且时间点很清楚：2023 年 3 月上线，2024 年 11 月 Agent 模式，2025 年后台任务。观众能看到“一个产品怎么长成另一个物种”。

### 为什么把 Claude Code/Codex 放一起

2025 年的两个标杆，代表两种形态：

- Claude Code：终端里的 Agent，强调“在你的项目里干活”。
- Codex：云端的 Agent，强调“并行任务”。

不要评“谁最强”。说“第一梯队”，说“各自擅长的任务不一样”。产品强弱每个月都可能换，绝对化会让课程很快过时。

### 为什么国内要单独讲

因为 Harness 是工程软件，不是基础模型科研。工程软件拼的是产品设计、工具生态、权限、上下文管理、用户体验，不是“谁的模型参数大”。国内团队在这些方面完全有能力做好。

同时要分清“模型”和“Harness”：

- Kimi、Qwen、GLM 是模型。
- Kimi Code、Qwen Code、ZCode 是 Harness。
- Trae、CodeBuddy 是 IDE/平台。
- WorkBuddy 是办公型 Agent。

这个区分很重要，否则观众会把“模型发布”当成“Harness 发布”。

### 为什么 DSH 用“插件树”讲

DSH 的差异化不在模型，而在架构：基于 Cordis 插件运行时，模型、工具、Skill、会话、沙箱、Agent Loop，全都是插件。连“循环”本身都可以被替换。

这不是说 Codex 没有插件或 MCP；它有。区别在开放程度：Codex 的核心循环由产品方封装，DSH 把核心循环也做成了可替换插件。“有插件”和“连循环都是插件”，是两个层级。讲的时候要讲清这个区别，不要把“开放程度不同”说成“有和无”。

还有一个对学习者很重要的点：DSH 把系统提示、工具调用、循环过程展示得很完整。你不是只看到一个黑盒答案，而是能看到它是怎么拼出来的。这也是你原稿里“推荐 DeepSeek”的真正理由——不是它跑分最高，而是它适合学习。

这意味着：你可以让 Harness 改自己的插件、加自己的功能。有人把它类比成“递归模型”，不准确；这不是模型在递归，是工具、文件系统、插件机制一起带来的自举能力。

顺便纠正一个容易混的说法：把 DSH 说成“基于 PiAgent”不够准确。更准确地说，它的运行时是 Cordis，Agent Loop 是插件，社区有 Pi → DSH 的架构对照。Pi 是另一套 Harness，不是 DSH 的内核。

### 对“最强/最好”的处理

原稿里有一些绝对化表达：“真正意义上当时实力最强的应该是 Claude Code”“DSH 是目前最好用或潜力最大”。

建议改成：

- “Claude Code 是当时的第一梯队，尤其在终端长任务上。”
- “DSH 是我个人认为潜力最大的一个，原因不是模型，而是插件化架构。”

把“事实”和“判断”分开。观众可以不同意你的判断，但不会觉得你在替厂商站台。

## 8. 第五幕：使用心法

### 先协议，后无状态

很多人一上来就讲“怎么省 token”，但新手不知道“token 花在哪”。所以先讲协议：

- 你看到的是聊天，实际传的是结构化消息。
- 主流三类：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages。
- 流式不是协议，是 SSE；协议是插座，流式是电线。

然后再讲“无状态”：大模型 API 默认不记得你，记忆是 Harness 每次重放上下文拼出来的。

### 笔记本比喻是整场的“认知锚点”

黑屋专家 + 笔记本，这个比喻能一次讲清四件事：

| 现象 | 比喻解释 |
| --- | --- |
| 换模型不断片 | 笔记本换一个专家，专家从第一页读 |
| 断网能继续 | 笔记本还在你手里，重新递进去 |
| 长对话贵 | 每轮专家都从第一页读到最后一页 |
| 何时新开 | 换一本干净的笔记本 |

这是整个下半场最值钱的部分。它不需要任何技术背景，但能直接指导行为。

### 从“贵”到“新开”

先让观众看到“长会话不是免费的记忆，而是每轮都重新买一遍”，再给五条新开规则：

1. 新任务，新会话。
2. 旧上下文和新问题无关，新会话。
3. 会话太长/上下文快满，先总结，再新开。
4. 换模型/换供应商，想干净一点，就新开。
5. 舍不得丢的结论，让 Agent 先写一份 handoff，再新开。

一句话：**一任务，一会话。**

### 工具/Skill/MCP：手/说明书/USB-C

三层要分清：

- 工具：模型的手。能执行动作，改变外部状态。
- Skill：说明书。告诉模型“这类任务怎么做”，按需加载。
- MCP：USB-C。让外部软件用统一协议把能力暴露给 Agent。

很多人把三者混成“都是插件”。讲清楚这三层，观众就能看懂 Harness 的能力边界。

### 行动循环：心跳

`模型 → 工具 → 观察 → 模型 → ……`，直到完成。

模型侧的一切控制，最后都会变成上下文里的文字；执行侧的一切能力，最后都会变成工具。前半句是提示词，后半句是工程。两半合起来，才是 Agent。

### 安全：不是附录，是必修

新手听完“AI 能操作电脑”，第一反应是“我也要装一个”。所以安全必须放在结尾前，而不是放在附录：

- 提示注入：网页/文件/邮件里的内容可能骗模型“忽略之前的指令”。
- 权限：目录、命令、网络、账号，都要设边界。
- 审批：高风险动作必须有人确认。
- 案例：2026 年 3 月，OpenClaw 因默认配置、插件生态、行为管控等问题被国内多个安全机构预警。

一句话：**能操作电脑，不等于可以随便操作。**

## 9. 视觉语言

### 为什么这个题目适合动画型演示

四个动词本身就是动作；参数、上下文、循环、工具调用都是“关系/过程”，静态图讲不清。传统 PPT 一页一条，会把这些关系切成碎片；动画能保持连续。

这个题目不是“配几张图”，而是“用运动来论证”：

- 棋子落下 → 看得见“看”；
- 滤镜扫过 → 看得见“特征”；
- 笔记本变厚 → 看得见“上下文成本”；
- 挽具扣上 → 看得见“Harness 把力量接到车上”；
- 权限门关上 → 看得见“安全边界”。

如果某个动画删掉后论证仍然完整，它就是装饰，删掉。

### 纸 → 屏幕

上半场用暖纸色，像一本历史书/笔记本；第三幕开始切到深色，像终端/黑屋。这个渐变对应“从描述世界到改变世界”。

- 第一幕：暖纸、青绿、手绘感；棋盘、滤镜。
- 第二幕：暖纸、暖黄、文字/打字机；聊天框、旋钮墙。
- 第三幕：过渡到深色、电光蓝；楼梯、循环、终端。
- 第四幕：深色、蓝紫；地图、插件树。
- 第五幕：黑屋、暖灯；笔记本、token 表、USB-C、权限门。

### 四幕四色

| 幕 | 颜色 | 用途 |
| --- | --- | --- |
| 看 | 青绿 `#2FB68A` | 棋盘、滤镜、数据 |
| 说 | 暖黄 `#E8B23A` | 文字、token、聊天 |
| 做 | 电光蓝 `#4C7DFF` | 循环、终端、工具 |
| 用 | 珊瑚红 `#E85B4A` | 警告、权限、重点 |

颜色只做“幕”的区分，不做装饰。一屏最多一个强调色。

### 五个反复出现的道具

1. **棋盘**：AlphaGo 的“看”。
2. **滤镜**：CNN 的“层层特征”。
3. **旋钮墙**：参数的“脑容量”。
4. **笔记本**：上下文的“记忆”。
5. **挽具/USB-C**：Harness 的“连接”。

这五个道具，构成整场的视觉记忆。观众看完，可能忘了年份，但会记得“那本越来越厚的笔记本”。

### 动画规则

- 一个镜头一个运动焦点。
- 入场 0.3–0.6 秒，`power2.out` / `power3.out`。
- 每次揭示后至少停 1 秒。
- 最后一帧稳定，不要卡在运动中间。
- 不用无限循环；需要循环时用有限次数。
- 不用未播种的随机数、`Date.now()`、`setInterval()` 做动画时钟。

### 禁止

- 机器人 stock photo。
- 品牌 logo 墙。
- 粒子特效堆叠。
- 用动画装饰“其实没有论证”的内容。

## 11. 事实与观点分开

### 三类信息

| 类型 | 例子 | 处理 |
| --- | --- | --- |
| 已核事实 | ChatGPT 2022-11-30 发布 | 直接写，附来源 |
| 产品数据 | DSH 日活 154 万（截至 2026-11-04） | 写日期和口径 |
| 个人判断 | “DSH 潜力最大” | 加“我的判断” |

### 产品名统一

原稿是语音转写，出现了很多误差：

- “Code Cloud” → Claude Code
- “Code Codex” → Codex
- “Coder Trace” → 待确认（可能是 Trae / Cursor / Codex 的口误）
- “Z-Code” → ZCode
- “Qwen-Coder” → Qwen3-Coder（模型）/ Qwen Code（CLI）
- “千问 Code” → Qwen Code
- “扣子” → Coze（扣子）
- “绘画” → 会话
- “High Friends” → HyperFrames（推测）
- “Openclaw” → OpenClaw
- “Workbuddy” → WorkBuddy
- “DeepSeek Harness” → DSH（首次出现写全称）

完整名称表见 `03-事实核查与纠错.md`。

### 对快速变化的产品

用“截至 2026-11-07”而不是“目前”。用“第一梯队”而不是“最强”。用“我的判断”而不是“事实证明”。

这不是胆小，是让课程活得久一点。

## 12. 希望观众带走什么

### 一句话

AI 从会看、会说到会做；Harness 是“做”的工程载体。

### 三个行动

1. 把一个真实任务交给 Harness，完整跑一周。
2. 一任务一会话；学会写 handoff。
3. 读一遍你的工具、Skill、MCP 配置，知道它能碰什么。

### 一个判断

Harness 是工程，不是魔法。理解了工程，你就不会被产品宣传牵着走。

这也是整场演讲的底气：我们不是在追一个又一个新工具，我们是在理解一套**让模型安全地改变世界**的方法。
