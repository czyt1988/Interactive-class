# 制作与拆分

> 这份文档解决三个问题：  
> 1. 34–35 分钟的长版，怎么拆成符合仓库契约的短课？  
> 2. HyperFrames 里每一屏怎么落地？  
> 3. 做完怎么验收，不把“看起来酷”当成“讲清楚了”？
>
> 先说明一个名字：你提到的“High Friends”，我按“HyperFrames”理解（本仓库的课程契约就是 HyperFrames 0.9.19 + GSAP）。如果其实是另一个框架，替换实现即可，脚本和分镜不变。Remotion 作为备选，见第 9 节。

---

## 1. 长版 → 课程版：9 集拆分

仓库契约要求：一门课 6–10 屏、2–5 分钟、一屏一个 scene。长版的 31 个镜头里，很多是 60–110 秒的“叙事段”，不能直接塞进一屏。拆法是：**把长镜头拆成 2–4 个 15–30 秒的“教学节拍”**，每个节拍一屏。

| 集 | 标题 | 长版镜头 | 时长 | 屏幕数 | 学完能 |
| --- | --- | --- | --- | --- | --- |
| E01 | AI 第一次看懂世界 | S01–S04 | 4:20 | 9 | 说出 AlphaGo 与 CNN 的关系；分清 2012 与 2016 |
| E02 | 文字接龙：从 GPT-1 到 GPT-3 | S05–S08 | 4:15 | 9 | 解释“猜下一个词”；说出参数不是智商 |
| E03 | ChatGPT 与大语言模型版图 | S09–S11 | 3:35 | 8 | 说出 ChatGPT 为什么震撼；知道 LLM 的极限 |
| E04 | 从聊天框到会干活的 Agent | S12–S14 | 3:35 | 8 | 分清 L1/L2/L3；说出 Agent 的四加一 |

### 拆分规则

1. **一个节拍一个论题**：能写出一句话论题，才配一屏；写不出就再拆。
2. **旁白不重写，只切片**：长版旁白已经按修正口径写好；拆屏时加 1–2 句过渡，不重新组织事实。
3. **每屏至少一个“看见”**：图、数字、动作、对比，四选一；不要一屏全是字。
4. **每屏 15–30 秒**：最长不超过 45 秒；超过就拆。
5. **最后一屏要能独立成立**：观众暂停在这一屏，也能读懂论题。

## 2. HyperFrames 落地

### 2.1 契约摘要

按仓库 `docs/course-contract.md`：

- 一门课一个 composition；一屏一个 scene。
- 画布 1920×1080，30fps。
- 目录：`courses/<slug>/course.json`、`STORYBOARD.md`、`composition/`。
- scene 文件是 `<template>`，不是完整 HTML；根用 `#root`，`position:absolute; inset:0`。
- 时间轴 `paused: true`，注册到 `window.__timelines["s-<id>"]`；用 `fromTo`，不用 `from`。
- GSAP、字体、图片全部本地；不引用 CDN。
- 单屏 10–30 秒，最长 45 秒；整门课 2–5 分钟。
- 最后 0.5 秒是稳定帧；不要卡在运动中间。
- 不使用 `Date.now()`、`setInterval()`、未播种的 `Math.random()` 做动画时钟。

> 当前仓库还是 v0.1 文档阶段，构建脚本尚未实现。以上是“契约口径”，实现时以契约为准；不要直接编辑 `dist/`。

### 2.2 根 composition 的写法

```html
<div
  id="s-hook"
  data-screen-id="hook"
  data-composition-id="s-hook"
  data-composition-src="compositions/01-hook.html"
  data-start="0"
  data-duration="18"
  data-track-index="0"
  data-track-kind="graphics"
  data-width="1920"
  data-height="1080"
></div>
```

- `data-start` / `data-duration` 用数字秒，不写表达式。
- host 按 `data-start` 升序；不重叠；根 `data-duration` 覆盖最后一屏。
- 不要在根 composition 里写导航、进度条、返回按钮；这些是课程外壳。

### 2.3 scene 的写法

```html
<template>
  <style>
    #root {
      position: absolute;
      inset: 0;
      background: #f4efe6;
      color: #141414;
      font-family: "Noto Sans SC", sans-serif;
    }
    #s-hook-title {
      position: absolute;
      left: 192px;
      top: 300px;
      width: 1536px;
      font-size: 132px;
      line-height: 1.1;
      font-weight: 700;
      letter-spacing: -0.02em;
    }
  </style>

  <div id="root" data-composition-id="s-hook" data-width="1920" data-height="1080">
    <h1 id="s-hook-title" class="clip" data-start="0.3" data-duration="17">
      三个画面，三次跃迁
    </h1>
  </div>

  <script>
    const tl = gsap.timeline({ paused: true });
    tl.fromTo(
      "#s-hook-title",
      { opacity: 0, y: 40 },
      { opacity: 1, y: 0, duration: 0.6, ease: "power3.out" },
      0.3,
    );
    window.__timelines["s-hook"] = tl;
  </script>
</template>
```

### 2.4 每集的工作流

1. 先写 `STORYBOARD.md`：学习者、学完能、屏幕表、参考。
2. 做第一屏；在 `composition/` 下跑 `npm run check`。
3. 用 `npm run snapshot` 看 0%、50%、90% 三个时间点。
4. 确认文字可读、构图稳定、最后一帧稳定。
5. 再做下一屏；每加一屏都重新 check/snapshot。
6. 接根 composition，跑构建；按报错补元数据/host。
7. 打开站点和独立静态服务器各走一遍；断网看 Network；键盘走一遍。
8. 开“减少动态效果”，确认不自动播放、讲义可读。

### 3.2 字体

- 中文正文：Noto Sans SC（本地 `woff2`，子集化）。
- 数字/英文标签：几何无衬线；等宽用于代码/API。
- 字号（1080p）：
  - 主标题 120–180px；
  - 章节标题 72–96px；
  - 正文 40–56px；
  - 标签/注释 28–36px；
  - 关键文字不小于 32px。

### 3.3 网格

- 安全区 90%；标题安全区 80%（左右至少 192px）。
- 中文每行 18–28 字；行高 1.5–1.7。
- 一屏最多两个文字层级。
- 数字和单位之间留空格；中英文之间留细空格。

## 5. 动画配方

### 5.1 棋盘（S03）

- 棋子按时间线逐颗出现，间隔 0.2–0.4s；不要一次全出。
- 镜头用 `scale` + `x/y` 推近到一角；不要用 3D 旋转。
- 三个标签“看/想/练”依次淡入；每个停留 0.8s。
- 最后定格在“4:1”，留 0.5s。

### 5.2 滤镜（S04）

- 像素图先马赛克化（用 CSS `image-rendering: pixelated` 或 SVG 网格）。
- 四层滤镜用半透明色块从左侧扫过；每层停留 0.6s。
- 应用带从右往左滑入；不要用无限滚动。
- 最后落回“2012 / 26.2% → 15.3%”。

### 5.3 旋钮墙（S07）

- 旋钮用 CSS grid 排列；按行/列 stagger 出现。
- 只让一个旋钮转动；其他保持静止，避免视觉噪音。
- 数字牌用 `fromTo` 从 0 跳到目标值；不要用 `setInterval`。

### 5.4 笔记本（S23–S25）

- 笔记本从门外飞入，用 `x` + `rotation`；不要用 3D 翻页库。
- 页码用 `textContent` 更新，或用多个页片叠加 + `opacity`。
- token 计数器随页码增长；最后停在具体数字。
- 换模型/断网用两个小场景切入，不要打断主画面。

### 5.5 挽具（S15–S16）

- 马先空跑（原地小幅上下），挽具从上方落下，扣住。
- 车被拉起时，车轮转动；用 `rotation` + `x`。
- 四个部件依次亮起；每个部件配一个短标签。
- 缰绳收紧用 `scaleX`，不要做“勒住”的暴力动画。

### 5.6 循环（S13、S29）

- 循环图用四个节点 + 箭头；一个点沿路径移动。
- 每到一个节点，旁边的文字/图标亮起。
- 不要无限循环；跑 2–3 圈后停在“完成”。
- 工具结果用“卡片飞回”表示；不要用粒子爆炸。

### 5.7 MCP（S28）

- USB-C 插入用 `y` + `scale`；四个外设依次亮起。
- 工具卡片展开；两个坐标点飞入画布；线从起点画到终点。
- 最后定格在“draw_line(x1, y1, x2, y2)”。

## 6. 音频与配音

- 默认无音频；如果做视频版，再开 `audio: true`。
- 每屏有语音，就必须有 `transcript`；这是无障碍要求。
- 语速 3.2–3.5 字/秒；反直觉事实后停 1.5 秒。
- 音乐：极简、低频；不要史诗预告片音乐。
- 音效：翻页、插头、键盘、盖章；少而准，不要每屏都响。
- 不要让音频自动播放；用“开始学习”手势解锁。

## 7. 验收清单

### 内容

- [ ] 每屏只有一个中心论题，能写出一句话。
- [ ] 术语第一次出现有解释或类比。
- [ ] 事实有来源；没有编造的数字、引文、结论。
- [ ] “最强/最好/潜力最大”都标了“第一梯队/我的判断”。
- [ ] 产品名按 `03` 的名称表统一。
- [ ] 讲义和屏幕文字一致，没有互相矛盾。

### 视觉

- [ ] 1920×1080；关键文字在 80% 标题安全区内。
- [ ] 正文 ≥ 40px；关键文字 ≥ 32px；对比度 ≥ 4.5:1。
- [ ] 中文每行 18–28 字；没有孤字、拥挤、溢出。
- [ ] 一屏不超过两个文字层级。
- [ ] 颜色、字体、圆角、留白和整门课一致。

### 动画

- [ ] 入场 0.3–0.6s；每次揭示后停 ≥ 1s。
- [ ] 最后 0.5s 是稳定帧；没有卡在运动中间。
- [ ] 没有无限循环；有限循环也停在稳定状态。
- [ ] 没有 `Date.now()`、`setInterval()`、未播种随机数。
- [ ] 没有同时用 CSS transform 和 GSAP 动画同一个元素的 transform。

### 技术

- [ ] `npx hyperframes@0.9.19 check` 通过。
- [ ] 每屏 0%/50%/90% 快照都看过。
- [ ] 没有外部请求、CDN、Google Fonts。
- [ ] GSAP、字体、runtime 都是本地文件。
- [ ] 根 `data-duration` 覆盖最后一屏；host 不重叠。
- [ ] 独立静态服务器打开正常；断网无外部请求。

### 播放体验

- [ ] 封面 → 第一屏正常；上一屏/下一屏正常。
- [ ] 暂停/继续/重播正常；讲义能打开。
- [ ] 键盘 ←/→/Space/F/T/Esc 正常。
- [ ] 深链 `#s=<id>` 打开后停在该屏。
- [ ] `prefers-reduced-motion` 下不自动播放。
- [ ] 手机横屏能看；竖屏能读讲义。

## 8. 风险与处理

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 产品数据变化快 | 课程很快过时 | 所有数据写“截至 2026-11-07”；每季度复核 |
| 2026 年产品难核实 | 容易写错 | 只用官方/主流媒体；不确定的不写 |
| 品牌/商标 | 侵权/广告嫌疑 | 不用 logo；只用文字名称；不做“排行榜” |
| 安全建议过时 | 误导新手 | 链接官方安全公告；强调“权限/沙箱/审批”原则 |
| 语音转写错误 | 产品名混乱 | 按 `03` 的名称表统一 |
| 长版镜头太长 | 不符合课程契约 | 按本文第 1 节拆成 15–30s 屏幕 |
| 动画过度 | 分散注意力 | 一个镜头一个运动焦点；删掉装饰动画 |

## 9. 如果改用 Remotion

Remotion 也可以做，而且更适合直接导出 MP4。但要注意：

- 本仓库的主链路是 HyperFrames 静态课程包，不把 MP4 作为主要分发格式（见 `AGENTS.md`）。
- 如果用 Remotion，建议把它当“附属产物”：同一份 `STORYBOARD.md`，先做 HyperFrames 课程版，再用 Remotion 导出一条 3–5 分钟的预告/社媒版。
- 不要把 Remotion 的 React SPA 塞进课程包；课程页不调用站点 API，也不引入 SPA 框架。
- 如果团队更熟 React，可以用 Remotion 做长版，但课程版仍按 HyperFrames 契约落地；两份共用素材和旁白，不要各写一套事实。

一句话：**Remotion 是输出渠道，HyperFrames 是课程运行时。别让工具反过来决定课程结构。**
