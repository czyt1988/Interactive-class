# 术语与类比

> 只收本课会用到的词。每个词给：一句话、一个类比、一个常见误解、出现位置。  
> 原则：第一次出现就解释；解释完立刻回到故事，不堆定义。

---

## 1. 参数（Parameter）

- **一句话**：模型里被训练出来的数字，决定它“看到什么输入、给出什么输出”。
- **类比**：一堵墙上的旋钮。训练就是反复调旋钮；参数越多，旋钮越多，能表达的模式越复杂。
- **常见误解**：“参数越多越聪明。”——不。参数只是“脑容量”的粗略指标；数据、算力、架构、对齐都影响表现。
- **出现**：S07、S08。
- **补充**：MoE（混合专家）模型有“总参数”和“激活参数”两个数字。DeepSeek-V3 是 671B 总参数、37B 激活；说“671B”时要说清是总参数。

---

## 2. 训练 / 推理（Training / Inference）

- **一句话**：训练是“调旋钮”，推理是“用调好的旋钮干活”。
- **类比**：训练像学生刷题、整理错题本；推理像考试时答题。考试时不再改脑子里的知识。
- **常见误解**：“我聊得越多，模型越懂我。”——默认不会。模型权重不会因为一次对话而改变；它只是在你这次请求的上下文里“临时记住”。
- **出现**：S07、S23。

---

## 3. Token

- **一句话**：模型处理文字的最小单位；可以是一个字、一个词、词的一部分，甚至一个空格。
- **类比**：把一句话切成积木块。模型不是按“字”读，而是按“块”读。
- **常见误解**：“一个汉字就是一个 token。”——不一定。不同模型的分词器不同；中文有时一个字一个 token，有时多个字一个 token。
- **出现**：S24。
- **补充**：上下文长度、计费、生成速度，通常都按 token 算。

---

## 4. 上下文窗口（Context Window）

- **一句话**：模型一次请求最多能“看到”的 token 数。
- **类比**：专家一次能读多厚的笔记本。超过这个厚度，前面的内容就装不下了。
- **常见误解**：“窗口很大，就可以永远不新开会话。”——不。窗口大不等于便宜，也不等于模型能均匀地注意每个位置；长上下文仍然会稀释重点。
- **出现**：S23、S24、S25。
- **补充**：Harness 通常会用“压缩/摘要”把长会话压进窗口；压缩会丢细节，重要结论要显式写下来。

---

## 5. 幻觉（Hallucination）

- **一句话**：模型生成看起来合理、但实际上错误或不存在的信息。
- **类比**：一个很会说话的实习生，不知道也会编，而且编得很像。
- **常见误解**：“它说得这么流畅，应该是对的。”——流畅度和正确性不是一回事。
- **出现**：S09（“什么都能答”之后，讲义里补一句）。
- **补充**：涉及事实、数字、引用、法律/医疗建议时，必须外部核实。

---

## 6. CNN（卷积神经网络）

- **一句话**：一种特别擅长处理图像的神经网络；通过一层层“滤镜”从像素里提取特征。
- **类比**：一层层滤镜：边缘 → 形状 → 眼睛/耳朵 → 猫。
- **常见误解**：“CNN 就是 AlphaGo。”——不是。AlphaGo 用了 CNN，但还用了搜索和强化学习；CNN 也不是 AlphaGo 发明的。
- **出现**：S04。

---

## 7. LLM（大语言模型）

- **一句话**：用海量文字训练、以“预测下一个 token”为核心任务的模型。
- **类比**：一个读了无数本书、特别会接话的人；它的底层动作是“接龙”，不是“查数据库”。
- **常见误解**：“LLM 是一个知识库。”——它把知识压缩在参数里，会记错、会编；它不是可检索的数据库。
- **出现**：S05–S11。

---

## 8. Agent（智能体）

- **一句话**：能围绕一个目标，在环境里反复“观察—行动—再观察”，并改变外部状态的系统。
- **类比**：一个能自己动手的实习生：你给目标，它自己找资料、改文件、跑测试、看结果、再改。
- **常见误解**：“写了系统提示词就是 Agent。”——那只是“角色扮演”；没有工具、循环、环境反馈，就只是一个聊天框。
- **出现**：S13、S14。

---

## 9. Harness（挽具 / 智能体运行框架）

- **一句话**：把模型装进一套工程系统里，让它能调用工具、管理上下文、执行循环、遵守权限的“运行时”。
- **类比**：马具/挽具。模型是马，Harness 是挽具，工具是车，权限是缰绳。
- **常见误解**：“Harness 就是 Agent 的另一个名字。”——不完全是。Agent 是“行为/产品”层面的词；Harness 是“工程/运行时”层面的词。两者看的是同一件事的两个角度。
- **出现**：S15、S16、S21。
- **补充**：Microsoft Learn 的定义是“runtime scaffolding that turns a language model into an agent that can perform work”，可以作为英文口径。

---

## 10. 工具调用（Tool Calling / Function Calling）

- **一句话**：模型输出一个结构化的“我要调用某个工具、参数是什么”的意图；Harness 解析并执行。
- **类比**：模型是大脑，工具是手；大脑说“拿杯子”，手去拿。
- **常见误解**：“模型真的执行了代码。”——不。模型只输出意图；真正执行的是 Harness/工具。
- **出现**：S13、S26。
- **补充**：现代 API 用结构化的 `tool_calls`，不是让模型直接输出一段裸 JSON 文本；教学上可以简化为“结构化意图”。

---

## 11. Skill（技能包）

- **一句话**：一段可复用的“怎么做这类任务”的说明书，通常是一个带 frontmatter 的 Markdown 文件，可附带脚本/资源。
- **类比**：书架上的操作手册。平时只看书脊（目录），要用时才抽出来翻。
- **常见误解**：“Skill 是模型的新能力。”——不。模型本身没变；变的是“它在正确的时候看到了正确的说明书”。
- **出现**：S27。
- **补充**：常见格式是 `SKILL.md`，开头写 `name` 和 `description`；Harness 先扫描目录，再按需加载。这叫“渐进披露”。

---

## 12. MCP（Model Context Protocol）

- **一句话**：一个开放协议，让软件用统一方式把自己的工具、数据、提示词暴露给 AI 应用。
- **类比**：AI 世界的 USB-C。以前每个外设一种接口，现在一个标准接口。
- **常见误解**：“MCP 是 Skill，或者是一个工具。”——不是。MCP 是协议；它可以让软件提供工具，但协议本身不是工具。
- **出现**：S28。
- **补充**：官方比喻就是“USB-C port for AI applications”；底层常用 JSON-RPC。

---

## 13. 系统提示词（System Prompt）

- **一句话**：Harness 在每次请求里放在最前面的“总规则”：你是谁、能做什么、不能做什么、输出格式是什么。
- **类比**：给演员的剧本扉页：角色、舞台规则、禁忌。
- **常见误解**：“系统提示词是绝对安全的。”——不。它会被提示注入攻击、会被长上下文稀释、会被工具输出污染。
- **出现**：S14、S29。

---

## 14. 行动循环（Agent Loop）

- **一句话**：`模型 → 工具 → 观察 → 模型 → ……`，直到任务完成或达到停止条件。
- **类比**：心跳。每跳一次，模型看一眼世界，做一个动作，再看一眼。
- **常见误解**：“循环越多次越好。”——不。循环要有停止条件、预算、超时、权限；否则会烧 token、卡死、重复劳动。
- **出现**：S13、S29。

---

## 15. 沙箱 / 权限（Sandbox / Permissions）

- **一句话**：沙箱限制 Agent 能碰的文件、命令、网络；权限决定某次高风险动作是否需要人批准。
- **类比**：给实习生一张门禁卡：能进哪几个房间、能开哪个柜子、动保险箱要不要叫经理。
- **常见误解**：“开了 Agent 就等于把电脑交给它。”——不。你可以只给它一个目录、一个只读环境、一个需要审批的命令白名单。
- **出现**：S30。
- **补充**：常见组合是“只读默认 + 写操作审批 + 目录白名单 + 网络白名单 + 命令超时”。

---

## 16. 协议（Chat Completions / Responses / Messages）

- **一句话**：Harness 和模型服务之间“怎么组织消息、怎么传工具、怎么收结果”的约定。
- **类比**：插座。不同国家的插座形状不同，但都是把电接进来。
- **常见误解**：“stream 是一种协议。”——不。流式是 SSE，一种传输方式；协议是消息格式。
- **出现**：S22。
- **补充**：很多厂商提供“OpenAI 兼容”接口，所以 Chat Completions 事实上成了行业通用语；Responses 是更新的接口；Anthropic Messages 是另一套。

## 附：三个最容易混的概念

### 模型 vs Harness

| | 模型 | Harness |
| --- | --- | --- |
| 是什么 | 大脑 | 挽具 + 手 + 记忆 + 权限 |
| 例子 | GPT、Claude、Kimi、Qwen、GLM | Claude Code、Codex、Cursor、Kimi Code、Qwen Code、ZCode、DSH |
| 谁提供 | 模型厂商 | 产品/工程团队 |
| 能不能换 | 可以（通过 API） | 可以（换一个 Harness） |

一句话：**模型决定“有多聪明”，Harness 决定“能不能干活、干得安不安全”。**

### Agent vs Harness

- **Agent**：行为层面的词。一个东西“是不是 Agent”，看它有没有目标、工具、循环、环境反馈。
- **Harness**：工程层面的词。一个东西“是不是 Harness”，看它有没有把模型、工具、上下文、权限、循环装成一套运行时。

同一个产品，可以既叫 Agent，又叫 Harness。不矛盾。

### 工具 vs Skill vs MCP

| | 是什么 | 类比 | 谁提供 |
| --- | --- | --- | --- |
| 工具 | 可执行的动作 | 手 | Harness 内置/插件 |
| Skill | 怎么做的说明书 | 操作手册 | 用户/团队/社区 |
| MCP | 连接外部软件的协议 | USB-C | 软件厂商/社区 |

一句话：**工具决定“能做什么”，Skill 决定“怎么做”，MCP 决定“能接什么”。**
