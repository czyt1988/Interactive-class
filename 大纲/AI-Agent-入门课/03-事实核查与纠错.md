## 1. 必须改的 10 条

### 1.1 “谷歌的 AlphaGo”

- **原稿**：“最早谷歌的 AlphaGo 打破了围棋的算法难度。”
- **核查**：AlphaGo 是 **DeepMind** 做的；谷歌 2014 年收购 DeepMind。说“谷歌旗下 DeepMind”可以，说“谷歌总部做的”不准确。
- **建议表述**：“2016 年，谷歌旗下 DeepMind 的 AlphaGo 以 4 比 1 战胜李世石。”
- **补充口径**：这是五番棋（五局定胜负），五局都下满；李世石赢下第 4 局，所以最终比分是 4:1，不要写成“李世石 4:1”。
- **来源**：[Google AlphaGo 官方博客](https://blog.google/innovation-and-ai/products/alphago-machine-learning-game-go/)、[China.org 4:1 报道](http://www.china.org.cn/sports/2016-03/15/content_38033103.htm)

### 1.2 “AlphaGo 就是卷积神经网络”

- **原稿**：“阿尔法狗……卷积神经网络开始应用到各行各业。”
- **核查**：AlphaGo 不是“纯 CNN”。它使用 **CNN 策略网络/价值网络 + 蒙特卡洛树搜索（MCTS）+ 监督学习/强化学习**。CNN 是“看棋形”的部分，不是全部。
- **建议表述**：“它用 CNN 看棋形，用搜索想几步，用自我对弈练自己。”
- **来源**：[Nature 论文](https://www.nature.com/articles/nature16961)、[AlphaGo Zero 官方博客](https://deepmind.google/discover/blog/alphago-zero-starting-from-scratch/)

### 1.3 “从 AlphaGo 开始，CNN 才应用到各行各业”

- **原稿**：“从 AlphaGo 开始，卷积神经网络开始应用到各行各业。”
- **核查**：CNN 的工业拐点是 **2012 年 AlexNet**，不是 2016 年 AlphaGo。AlexNet 在 ImageNet 上把 Top-5 错误率从 26.2% 降到 15.3%，之后 CNN 进入医疗影像、工业质检、人脸识别、OCR 等领域。AlphaGo 是“大众认知拐点”。
- **建议表述**：“CNN 的工业拐点是 2012 年；AlphaGo 让大众第一次看见它会看。”
- **来源**：[AlexNet 论文](https://papers.nips.cc/paper/2012/hash/c399862d3b9d6b76c8436e924a68c45b-Abstract.html)

### 1.4 “ChatGPT 是 OpenAI 最早的版本”

- **原稿**：“OpenAI 的 ChatGPT 最早版本的出现……它是哪一年出现的？”
- **核查**：ChatGPT 于 **2022 年 11 月 30 日**上线；OpenAI 最早的语言模型是 **2018 年的 GPT-1**。ChatGPT 不是 OpenAI 的第一款模型产品，也不是“最早版本”。
- **建议表述**：“ChatGPT 2022 年 11 月 30 日上线；OpenAI 最早的语言模型是 2018 年的 GPT-1。”
- **来源**：[OpenAI Introducing ChatGPT](https://openai.com/index/chatgpt/)、[OpenAI GPT-1](https://openai.com/index/language-unsupervised/)

### 1.5 “ChatGPT 的参数是 1750 亿”

- **原稿**：“当时最早版本的 OpenAI 参数是多少？”
- **核查**：要分两种问法：
  - 如果你问的是 **OpenAI 最早的语言模型 GPT-1**：**1.17 亿（117M）**。
  - 如果你问的是 **ChatGPT 首版**：OpenAI **没有公布** GPT-3.5 的参数量；外界常说的“1750 亿”是 **GPT-3** 的数字，不是 ChatGPT 的官方数据。GPT-4 也没有公开。
- **建议表述**：“GPT-1 是 1.17 亿；GPT-3 是 1750 亿；ChatGPT 用的 GPT-3.5 没有公布参数量，外界传的 1750 亿是推测，不是官方数据。”
- **来源**：[GPT-3 论文](https://arxiv.org/abs/2005.14165)、[GPT-1 论文](https://cdn.openai.com/research-covers/language-unsupervised/language_understanding_paper.pdf)、[GPT-4 技术报告](https://arxiv.org/abs/2303.08774)

### 1.6 “参数到一定量级，智力就突然上来了”

- **原稿**：“好像参数达到一定量级之后，智力就突然上来了。”
- **核查**：这句话“半对”。
  - 规模定律是真的：参数、数据、算力增加，能力会稳定提升。
  - “涌现”是 2022 年提出的假说：有些能力在小型模型上没有、在大型模型上突然出现。
  - 但 2023 年有论文指出：部分“突然”可能是评测指标造成的；换个线性指标，曲线会变平滑。
  - 更重要的反例：**InstructGPT 1.3B 在人类偏好上赢过 GPT-3 175B**。说明“对齐”是独立变量，不是参数量的自动产物。
- **建议表述**：“看起来像突然开窍；更准确地说，参数、数据、算力、对齐，四件事一起跨过阈值。学界对‘涌现’还有争论。”
- **来源**：[Scaling Laws](https://arxiv.org/abs/2001.08361)、[Emergent Abilities](https://arxiv.org/abs/2206.07682)、[Are Emergent Abilities a Mirage?](https://arxiv.org/abs/2304.15004)、[InstructGPT](https://arxiv.org/abs/2203.02155)、[Chinchilla](https://arxiv.org/abs/2203.15556)

### 1.7 “Cursor 是 2024 年出现的”

- **原稿**：“像 Cursor，它在 2024 年就出现了。”
- **核查**：Cursor 于 **2023 年 3 月 14 日**上线；**2024 年 11 月 24 日**才引入编码 Agent。2023 年是 IDE/补全，2024 年底才是 Agent 模式。
- **建议表述**：“Cursor 2023 年 3 月上线；2024 年 11 月有了 Agent 模式。”
- **来源**：[MIT AI Agent Index · Cursor](https://aiagentindex.mit.edu/2024/cursor-agent/)

### 1.8 “OpenAI 的 stream 协议”

- **原稿**：“接口主要有三大类：最常见的 OpenAI chat 协议；OpenAI 的 stream 协议；Anthropic 公司的协议。”
- **核查**：流式（stream）不是独立协议，而是 **SSE（Server-Sent Events）** 这种传输方式。协议家族通常是：
  - OpenAI **Chat Completions**
  - OpenAI **Responses**
  - Anthropic **Messages**
  - （还有 Google Gemini 等，但入门课不必展开）
- **建议表述**：“主流是三类协议：Chat Completions、Responses、Messages；流式是 SSE，不是独立协议。协议是插座，流式是电线。”
- **来源**：[OpenAI Responses API](https://openai.com/index/new-tools-for-building-agents/)、[MDN SSE](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)

### 1.9 “大模型服务器不生成会话，也没有会话概念”

- **原稿**：“远端的大模型是没有这种会话概念的”“所有大模型请求都没有所谓的会话”。
- **核查**：**API 默认无状态**，这句话在“每次请求都要自带上下文”的意义上是对的。但产品层可以存会话：ChatGPT 网页会保存对话；OpenAI Responses API 支持 `store`；Assistants API 有 thread。更准确的说法是：
  - 模型 API 默认不替 Harness 保存“这次任务”的状态。
  - Harness 仍然每次把上下文重放给模型。
  - 产品层可以额外提供会话存储，但那是产品能力，不是模型本身“记得你”。
- **建议表述**：“大模型 API 默认无状态；产品层可以帮你存会话；但 Harness 每次请求仍然要把上下文重放。”
- **来源**：[OpenAI Responses API](https://openai.com/index/new-tools-for-building-agents/)、[OpenAI Chat Completions 文档](https://platform.openai.com/docs/api-reference/chat)（抓取时被 Cloudflare 拦截，仅作入口引用）

### 1.10 “DeepSeek Harness 是基于 PiAgent”

- **原稿**：“DeepSeek Harness 是基于 PiAgent 来做底层行动循环的支撑。”
- **核查**：更准确的说法是：DSH 基于 **Cordis** 插件运行时；模型、工具、Skill、会话、沙箱、**Agent Loop** 都是插件。社区有 `pi2dsh` 这类 Pi → DSH 的架构对照/桥接工具，但这不等于“DSH 的内核是 PiAgent”。Pi 是另一套 Harness。
- **建议表述**：“DSH 的运行时是 Cordis，Agent Loop 是插件；社区有 Pi → DSH 的架构对照。Pi 是另一套 Harness，不是 DSH 的内核。”
- **来源**：[腾讯云：DSH 插件运行机制](https://cloud.tencent.cn/developer/article/2740489)、[pi2dsh](https://pi.dev/packages/pi2dsh)、[DSH 子系统文档](https://github.com/deepseek-ai/deepseek-harness/blob/fcc0ad462172522aaf5c93a7b2e01f6b9f0b0159/docs/subsystems/README.zh.md)（GitHub 抓取失败，仅作入口引用）

## 2. 建议改的 8 条

### 2.1 “Claude Code 是当时最强的”

- **原稿**：“真正意义上当时实力最强的应该是 Claude Code。”
- **核查**：Claude Code 是 2025 年很有代表性的终端 Agent，尤其在终端长任务上；但“最强”“第一梯队”这类排名会随模型版本、任务类型、评测口径变化。Claude Code 2025-02-24 研究预览，2025-05-22 正式发布。
- **建议**：“Claude Code 在终端长任务上很有代表性。”

### 2.2 “DSH 是目前最好用/潜力最大”

- **原稿**：“我认为这是目前最好用或者是潜力最大的智能体。”
- **核查**：这是个人判断，不是评测结论。DSH 的差异化在插件化架构，不在“全面跑分”。
- **建议**：“这是我个人的判断：DSH 的潜力最大，原因不是模型，而是插件化架构。”

### 2.3 “OpenClaw 是 2026 年出来的”

- **原稿**：“OpenClaw 是 2026 年出来的时候突然火了。”
- **核查**：OpenClaw 的前身 **Clawdbot** 由 Peter Steinberger 在 **2025 年 11 月**发布；后改名 Moltbot，再改名 OpenClaw；**2026 年 1 月底**在社交平台爆红。2026 年 2 月，创始人加入 OpenAI，项目转入基金会。
- **建议**：“2025 年 11 月以 Clawdbot 出现，2026 年 1 月改名 OpenClaw 并爆红；2 月创始人加入 OpenAI。”

### 2.4 “真正意义上的智能体是 2025 年中之后才流行的”

- **原稿**：“真正意义上的智能体（或者叫 harness），其实是从 2025 年年中之后开始流行的。”
- **核查**：概念更早：AutoGPT 2023 年 3 月、Devin 2024 年 3 月、Cursor Agent 2024 年 11 月。2025–2026 是“真正好用、真正出圈”的拐点，不是“概念第一次出现”。
- **建议**：“2023 年就有 AutoGPT，2024 年有 Devin/Cursor Agent；2025–2026 才是真正好用、出圈的拐点。”

### 2.5 “AI 全程操作你的电脑”

- **原稿**：“现在基本上 AI 全程操作你的电脑了。”
- **核查**：Agent 是在权限、沙箱、审批的边界内操作；不是无条件接管。OpenClaw 2026 年 3 月被国内多个安全机构预警，就是例子。
- **建议**：“它能在你授权的目录、命令、网络范围内操作；不是无条件接管。”

### 2.6 “MCP 是一种特殊的 Skill”

- **原稿**：“MCP 也一样，你可以把它理解为一种特殊的 Skill 或者是一个工具调用。”
- **核查**：MCP 是**协议**（基于 JSON-RPC），让软件把 tools/resources/prompts 暴露给 Agent；Skill 是**知识/流程包**。两者不是一回事。
- **建议**：“MCP 是协议，不是 Skill；它让软件用统一方式把能力暴露给 Agent。”

### 2.7 “Agent 就是一种提示词注入”

- **原稿**：“无论如何，Agent 都是一种提示词的注入。”
- **核查**：模型侧的控制确实最终变成上下文/提示词；但 Agent 还包括工具执行、权限、沙箱、循环、状态管理。只说“提示词注入”，会把 Agent 说成“更长的 prompt”，低估了工程部分。
- **建议**：“模型侧的一切控制最终是提示词；执行侧的一切能力最终是工具。两半合起来才是 Agent。”

### 2.8 “参数越多越聪明”

- **原稿**：隐含在“参数达到一定量级，智力突然上来”里。
- **核查**：参数只是“脑容量”的粗略指标；数据质量、算力、架构、对齐、推理时计算都影响表现。InstructGPT 1.3B 在人类偏好上赢 GPT-3 175B 是最好的反例。
- **建议**：“参数是脑容量的粗略指标，不是智商。”

## 9. 核查方法说明

### 来源分级

| 级别 | 类型 | 用法 |
| --- | --- | --- |
| A | 官方博客/论文/官方文档 | 直接作为事实依据 |
| B | 主流媒体/研究机构 | 作为交叉验证；标注“据……” |
| C | 社区文章/百科/厂商宣传页 | 只作线索；不单独作为关键事实 |
| D | 传闻/推测 | 不写进正式稿 |

### 抓取限制

以下页面在核查时遇到反爬、登录墙或跨域跳转，只作为入口引用，不作为唯一依据：

- Wikipedia（ChatGPT、AlphaGo、Cursor）
- GitHub（DSH README、pi2dsh）
- OpenAI Platform Docs（Cloudflare 403）
- Anthropic Docs（跨域跳转）
- Reuters（抓取失败）
- 百度百科（403）

对这些问题，本文优先使用可访问的官方博客、论文摘要、主流媒体和 MIT AI Agent Index 交叉核对。关键数字至少有两个来源，或明确标注“单一来源/媒体统计”。

### 产品数据的时效性

AI 产品数据变化很快。本文所有产品数据都写了日期和口径；正式讲课前，建议再核对一次：

- DSH 的 DAU/插件数
- WorkBuddy 的任务请求数
- OpenClaw 的版本/安全公告
- Claude Code / Codex / Cursor 的最新版本

不要把“截至某日”的数据说成“现在”。
