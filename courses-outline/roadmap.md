# 从 AI 小白到 AI 达人：后续课程规划

> 状态：规划稿 v0.1 · 2026-11-13
> 上游：第一课《从会聊天到会干活：AI Agent 入门》（`courses/ai-first-sees/`，28 屏 / 29:54）
> 体例：本文只定「讲什么、怎么切场景、先做哪门」。每门课立项时，再按 `courses-outline/ai-first-sees/outline.md` 的体例写逐页脚本与旁白；本文的场景表就是那一步的输入。
> 资料口径：工具与型号月月变，本文只写到「某类工具/某类做法」，具体产品名以立项时的复核结果为准。

## 0. 先看结论

- 第一课解决**看懂**：AI 十年怎么走到 Agent，Agent 怎么运转，为什么「记忆在 Harness，不在模型」。
- 后续课程解决**用好、做出来、搭起来、带别人用**。
- 课程体系 = **1 条基础主线 + 2 条分岔路线 + 1 条达人合流 + 1 条通识线**：

| 层 | 给谁 | 课程数 | 回答的问题 |
| --- | --- | --- | --- |
| 基础必修 | 所有人 | 4 | 提示词、模型与工具、判断力、工作区记忆 |
| 非编程路线 | 没有编程经验的人 | 11 | PPT / 文档 / 表格 / 调研 / 内容；零代码 Web coding；自动化与个人 Agent |
| 编程员路线 | 程序员、技术负责人 | 11 | AI 辅助编程工作流、调试与评审、上下文工程、多 Agent、安全与团队落地 |
| 达人合流 | 两条路线走到后面的人 | 3 | 做一个真正的项目；把 AI 变成自己的工作系统；持续跟上变化 |
| 通用能力 | 所有人 | 5 | 写作、表达、学习、数据素养、职业地图（非 AI 主题，AI 只当陪练） |

合计新增 **34 门课**（每门 8–12 屏、5–9 分钟），约 **337 屏**、**4–5 小时**；分三波建设。

- **课程形态**：后续课程不做第一课那种 30 分钟长视频，统一做「旁白驱动的小课」：8–12 屏、5–9 分钟、一屏一条旁白、连续播放。这个时长介于课程契约现有的短课（2–5 分钟）与长视频（25–35 分钟）之间，需要先在契约里补一档中课口径（见 3.4）。
- 学完的标志不是「会用很多工具」，而是能独立完成三件事：
  1. 用 AI 交付一份别人愿意看的专业成果（PPT、报告、数据、网页都算）；
  2. 做一个自己每天真的会用的小产品、小工具或自动化流程；
  3. 把自己的方法写下来、讲清楚，并随工具变化持续更新。

### 1.2 六个缺口

1. **会说不等于会写提示词。** 第一课解释了「你的问题只是最后一页」，但没教怎么写出有效的前几页：角色、上下文、示例、输出格式、迭代。
2. **知道工具不等于会选工具。** 没有模型/工具的全景与选型方法：什么任务用什么模型、什么任务根本不该用 AI、成本与延迟怎么权衡。
3. **理解风险不等于守得住。** 幻觉、事实核查、隐私、版权、伦理分散在各屏，没有变成可执行的检查清单与边界。
4. **不会「做出来」。** 听众看完能解释 Agent，却做不出一份 AI 协作的 PPT、一张清洗过的表、一个能打开的网页或一个能跑的工作流。
5. **程序员缺工作流。** 第一课站在「使用者」视角讲 Agent；程序员需要的是需求澄清、规格、计划、调试、测试、评审、重构、上下文工程这一整套协作流程。
6. **不会构建与治理。** 搭自己的 Agent/工作流、写 Skill 与 MCP、设计评测与权限、带团队落地，这些是「达人」与「熟练用户」的分水岭。

### 1.3 后续课程不重复清单

后续课程立项时，以下内容默认不再用整屏讲，只在需要时一句话带过：

- AI 十年史、CNN/AlphaGo、Scaling Law、涌现（第一课 S03–S06）
- Agent 定义、L1–L3、Harness 四件套、工具/Skill/MCP 的本质（S08–S13）
- 无状态与笔记本比喻、长会话成本、上下文压缩的基本原理（S17–S19）
- AGENTS.md 的基本概念（S20–S21）；后续只在「怎么写好、怎么维护、多工具兼容」上加深
- 「一句话背后是几万 token」的上下文组装原理（S22）
- 产品版图与公司路线（S14–S16）

## 2. 学习者与能力阶梯

### 2.1 三类学习者

| 画像 | 现在的状态 | 想要的结果 | 主路线 |
| --- | --- | --- | --- |
| A 职场白领（非技术） | 用过对话式 AI，会问会答，日常重复劳动多 | 把 AI 变成办公生产力：PPT、文档、表格、调研、自动化 | 基础必修 → 办公创作 → 零代码构建 → 自动化 |
| B 创作者 / 自由职业 / 小团队主理人 | 会用 AI 做内容，但不成体系，做不出产品 | 能独立做出网页、工具、自动化，能接活、能交付 | 基础必修 → 零代码构建 → 办公创作 → 达人合流 |
| C 程序员 / 技术负责人 | 会用补全，没形成 AI 协作工作流；或团队想落地 | 提效同时保住质量与安全；能设计 AI 应用、带团队用 | 基础必修 → 编程路线 → 达人合流 |

管理者的需求（团队规范、ROI、安全）不单独开线，放在 D11《团队怎么用 AI》与 X2《AI 工作系统》里。

### 2.2 五级能力阶梯

| 级别 | 一句话定义 | 可观察的能力 | 对应课程 / 检查点 |
| --- | --- | --- | --- |
| L1 会用 | 能安全地使用对话式 AI 完成日常小任务 | 完成「提问→取回→采用或弃用」的闭环；分清事实与建议；按任务新开或结束会话 | 第一课；检查点：用 AI 完成一次真实小任务并写 3 行取舍 |
| L2 说清 | 能把任务写成可执行请求，并核验输出 | 写全任务、背景、约束、验收；给最小必要上下文；三查事实并留记录；按结果定向改一轮 | F1 + F3；检查点：同一任务的 before/after 提示词 + 一份核验记录 |
| L3 会做 | 能借助 AI 做出可交付的成果 | 做出 PPT、文档、表格、网页、小工具中的至少三种；能验收与排错；能沉淀模板与检查清单 | O1–O5、W1–W4、A1–A2 任一；检查点：3 件可展示作品 |
| L4 会搭 | 能搭工作流与 Agent，并设计边界 | 写项目记忆与技能；接工具/MCP；设权限与评测；用 AI 完成一个真实项目 | F4 + D1–D7 + A2 + X1/X2；检查点：一个跑起来的 Agent/工作流 + 项目复盘 |
| L5 达人 | 能建体系、定规范、带别人用 | 写团队规约；做评审与安全审计；量化 ROI；持续更新方法库并教人 | D9–D11 + X3；检查点：一份团队规约 / 一次内部分享 / 一个在维护的模板库 |

> 说明：级别不是升级打怪，L3 与 L4 按路线分岔。非编程路线走到 L3 已经很能打（办公达人）；程序员的目标通常是 L4；技术负责人走 L5。

### 2.3 两条路线怎么走

**非编程路线（A/B 画像）**

```text
第一课（看懂）
  → F1 说清 → F3 判断 → F2 选型 → F4 记忆
  → O1 PPT → O2 文档 → O3 表格 → O4 调研 → O5 图/视频（可选）
  → W1 第一个网页 → W2 交互与数据 → W3 小工具与脚本 → W4 做一个产品（capstone）
  → A1 工作流 → A2 个人 Agent（非编程）
  → X2 工作系统 / X3 持续学习
```

**编程员路线（C 画像）**

```text
第一课（看懂）
  → F1 说清 → F3 判断 → F2 选型 → F4 记忆
  → D1 AI 编程入门 → D2 需求与计划 → D3 调试 → D4 测试与评审 → D5 重构与遗留代码
  → D9 安全与工程底线（可提前到 D1 之后）
  → D6 项目记忆进阶 → D7 Skill 与 MCP → D8 多 Agent
  → D10 AI 原生架构 → D11 团队落地
  → X1 项目课 / X3 持续学习
```

### 2.4 「达人」的结业标准

不考试，看作品。每位学员在完成对应路线后交三件东西（可作为结业页/作品墙的雏形）：

1. **一份专业成果**：用 AI 协作完成的 PPT / 报告 / 数据分析，附「AI 做了什么、我改了什么」的复盘。
2. **一个能跑的东西**：一个网页、一个小工具、一条自动化流程或一个 Agent，附使用说明与权限边界。
3. **一套可复用的方法**：一份自己的 AGENTS.md / 提示词库 / 检查清单，附「踩过的坑」三条。

程序员版把第 1 件换成「一个 AI 协作完成的项目 + 评审记录」，把第 3 件换成「项目记忆 + 技能库」。三件作品能同时交出来，就是 L4；能把它复制给团队并持续维护，就是 L5。

### 3.3 前置关系与共用资产

- 所有课程默认前置第一课；但每门课都要能在「没看过第一课」时单独成立（`prerequisites` 里写清即可，不强制串行）。
- 公共基础顺序：第一课 → F1（说清）→ F3（判断）→ F2（选型）→ F4（记忆）。F4 之后两条路线正式分岔。
- 共用资产：真实产品截图/logo 素材库、事实核查表、AGENTS.md 模板、PPT 模板、练习素材包。第一课已经把 `composition/assets/media/` 的素材规范跑通，后续课程复用同一套目录约定。
- 练习资料：课程包里的 `composition/assets/` 会随构建整体复制进 `dist/`，所以练习表、模板、检查单可以作为**静态直链**分发，不需要先做平台功能；课程页加「资料区」是后续体验增强。
- 术语表：延续第一课的口径（Harness、上下文、Skill、MCP 等），后续课程第一次出现时仍要一句话解释。

### 3.4 课程形态与契约调整建议

现有课程契约只有两档：短课 6–10 屏 / 2–5 分钟（单屏 ≤45 秒），和长视频课（样板 28 屏 / 29:54，上限 30 屏 / 35 分钟）。本规划主力的 8–12 屏 / 5–9 分钟正好落在中间，建议先补一档「旁白小课」，再批量生产。

**推荐形态（本规划全部课程默认）**
- 8–12 屏，单屏 35–70 秒，总 5–9 分钟；一屏一条旁白，屏内用连续动画讲完一个点。
- `audio: true`、`playback: "continuous"`、每屏 `transcript` 与旁白一致；字幕在画布内，播放器提供暂停/字幕/配音开关（沿用第一课已验证的链路）。
- 亮色纸面、一屏一个论点、一个强调色；真实界面与 logo 只做小证据卡。

**需要同步的契约与文档修订**（建议作为一门平台任务，先于第二门课）
1. `docs/course-contract.md` §4.5 / §4.11 增加「旁白小课」档：8–12 屏 / 5–10 分钟 / 单屏 ≤70 秒。
2. `DESIGN.md` 8.4 增加旁白小课的视觉规则（沿用现有字号、旁白条与四幕强调色，不新增令牌）。
3. `course-template/` 的作者文档、`docs/agent-development-plan.md` §14.1 的默认屏数同步更新。
4. 顺手修掉平台盘点发现的文档矛盾：`>15 屏拆系列` 与 28 屏样板冲突；`playback` 字段没进字段表；§5.2 错误码表缺 `asset_missing` / `forbidden_clock`；§2 目录树画了不存在的 `hyperframes.json`；backlog 里「语音讲解未做」已过时。
5. **平台前置（P0）**：`scripts/build_narration.py`、`scripts/curate_narration.py`、`scripts/prepare_course_media.py` 写死了 `ai-first-sees`，必须先参数化，否则第二门旁白课做不了；CI 质量门（check / snapshot / axe / 独立部署 / 预算）也要先补，30 门课靠人工验收必漏。

**不做什么**：不为每门课定制外壳；不做 11–20 屏却没有旁白的中间态；不把长视频当主力。

## 4. 基础必修

四门课只补操作层，不复述第一课的史、定义与 Harness 解剖。推荐顺序：第一课 → F1 → F3 → F2 → F4（F1 打底，F3 立边界，F2 学选型，F4 做沉淀）。

### F1 · 提示词与上下文：把话说清楚

- **定位**：说清与说不清差一个结果；用四块结构写请求，用最小上下文喂材料。
- **受众与前置**：看过第一课的所有学习者；用过聊天或 Agent，无编程基础。
- **学完能**：① 用「任务、背景、约束、验收」四块写出一条可执行请求；② 判断哪些上下文该喂、放在哪（对话、文件、链接或让它自己找）；③ 按第一轮结果定向修改，而不是重写提示词。
- **场景（9 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 同一句话，两种结果 | 两窗对比：左空话、右可用稿；差距在输入 |
| S02 | four-blocks | 一条请求的四个格子 | 任务、背景、约束、验收；像快递单一样拆一条真实请求 |
| S03 | verb | 动词要可验收 | 「优化一下」改成「压成 3 段、保留数字」；用可验收的动词 |
| S04 | context-min | 上下文给最小必要 | 一摞资料对比三份必要材料；给相关的，不给全部 |
| S05 | context-where | 放哪儿比说什么重要 | 一次性进对话、长期进文件、公开网页给链接；长期上下文放工作区 |
| S06 | example | 一个例子顶十句形容 | 一句「正式一点」对一份样例；能示范就别形容 |
| S07 | output-shape | 先说清楚要什么形状 | 邮件、清单、表格、大纲四张卡；输出格式也是验收标准 |
| S08 | iterate | 先让它反问，再改一轮 | 补约束、点错处、加例子三条返工路径；改一句比写十句省 |
| S09 | close | 三句话带走 | 四块模板、最小上下文、定向返工三张收尾卡 |

- **交付物**：提示词四块卡（一条真实请求的 before/after）+ 上下文清单（必给、可给、不给三类）。
- **风险**：提示词方法多为经验，无统一标准，不承诺某句式一定有效；token 与窗口数字月月变，只讲方法。
- **优先级**：P0。

### F2 · 模型与工具全景：什么任务用什么 AI

- **定位**：不追新品，先看任务；用一张「任务 × 形态」地图，把问、查、写、算、画、做、连匹配到合适的 AI。
- **受众与前置**：第一课 + F1；无编程基础。
- **学完能**：① 把任务归到七类并匹配工具形态；② 按能力、上下文、速度、价格、多模态五轴做选型并说明理由；③ 判断该用聊天、工作流还是 Agent，以及何时换工具。
- **场景（9 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 同一任务，三种结果 | 做 PPT 三窗对比：只给提纲、给成品、每天自动更新；形态要匹配任务 |
| S02 | task-map | 七类任务 | 问、查、写、算、画、做、连，七张任务卡各配交付物 |
| S03 | shape-fit | 四种形态是分工不是等级 | 聊天、专用模型、工作流、Agent 各有位置；可控度与自动化四象限 |
| S04 | model-axes | 选模型的五个轴 | 能力、上下文、速度、价格、多模态；没有最强，只有最合适 |
| S05 | cost-tier | 贵的用在刀刃上 | 判断写作给强模型、抽取整理给快模型，成本条对比 |
| S06 | deploy | 数据决定部署 | 云端、企业版、本地私有化三档；数据不能出内网才谈本地 |
| S07 | agent-fit | 什么时候值得上 Agent | 多步骤、碰文件系统、有明确验收、可回滚，四问清单 |
| S08 | switch | 换工具不换方法 | 工作区、提示词、验收标准可迁移；投资方法，不押产品 |
| S09 | close | 一张选型卡 | 任务、形态、模型、风险四问 |

- **交付物**：任务选型表（5 个真实任务）+ 降本实验（同一任务强模型与快模型各跑一次，记质量与成本差）。
- **风险**：型号、价格、上下文、多模态支持与本地部署成本月月变；只讲分类与判断法，不排名。
- **优先级**：P1。

### F3 · AI 的判断力：幻觉、隐私、版权与伦理

- **定位**：AI 的输出是草稿不是结论；学会核验真假、守住数据边界、看清版权与责任。
- **受众与前置**：第一课 + F1；所有岗位。第一课 S27 讲「哪些不能给」，本课讲「怎么判断、怎么留痕、谁负责」。
- **学完能**：① 用「三查」识别幻觉与不可靠数字，并留下核验记录；② 把材料按可给、脱敏后给、不给分级，说出依据与审批人；③ 在版权、披露、责任三个场景里做对选择。
- **场景（10 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 一份看起来很对的报告 | 报告被红笔圈出编造引用、过期数字、张冠李戴；流畅不等于正确 |
| S02 | hallucination | 幻觉从哪来 | 它在生成最像答案的文本；模型没有「查证」这一步 |
| S03 | three-checks | 三查 | 来源可点开、两个独立来源、时效；关键事实至少过一关 |
| S04 | numbers | 数字、引用、法规最危险 | 编造的 DOI、链接、法条也像真的；回原始来源 |
| S05 | data-class | 数据先分级再决定 | 可给、脱敏后给、不给；脱敏三步：删、替、泛化 |
| S06 | data-path | 你的数据走哪条通道 | 个人版、企业版、API 的留存与训练设置不同 |
| S07 | copyright-in | 输入端版权 | 上传他人文章、图片、付费课改写有侵权、违约、泄密三重风险 |
| S08 | copyright-out | 输出端版权 | 可版权性与商用条款因平台、地区而异；商用前查条款 |
| S09 | ethics | 披露与责任 | 对外材料、招聘、客服要披露 AI 参与；谁签字谁负责 |
| S10 | close | 三问带走 | 真的吗、能给它吗、谁负责 |

- **交付物**：三查核验记录（对一份 AI 产出标出改动与依据）+ 岗位数据分级表（10 类材料）。
- **风险**：版权与数据政策按国家、平台、合同不同且在变，不构成法律意见；案例用公开事实或虚构。
- **优先级**：P0。

### F4 · 工作区的记忆：AGENTS.md 与 Skill

- **定位**：把每次重新解释变成一次写好、每次自动带上：建工作区、写记忆、沉淀技能。
- **受众与前置**：第一课 + F1；用 AI 做长期项目的人（PPT、调研、内容、活动）。
- **学完能**：① 为非编程项目建工作区并写 AGENTS.md，让新会话快速进入状态；② 判断什么该写、什么不该写；③ 把重复三次以上的流程写成一个 Skill，并知道何时淘汰。
- **场景（10 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 第 20 次解释同一个项目 | 每次粘贴同一段背景，对比有 AGENTS.md 的目录；记忆写进工作区 |
| S02 | workspace | 先建一个工作区 | 项目文件夹俯视图：素材、背景、产出、旧版、AGENTS.md |
| S03 | memory-layers | 三层记忆 | 全局偏好、项目记忆、本次会话；各写在哪、活多久 |
| S04 | agents-md-blocks | AGENTS.md 四块（通用版） | 是什么、在哪、规矩、进度；只写「不写就会重复解释」的内容 |
| S05 | agents-md-ppt | PPT 项目示例 | 素材、受众、风格、页数、禁忌、进度 |
| S06 | agents-md-research | 调研项目示例 | 问题清单、来源清单、判断与未决、引用格式 |
| S07 | skill-when | 什么时候该写 Skill | 同一流程做到第三次；重复三次再写，一次性不写 |
| S08 | skill-write | 写第一个 Skill | SKILL.md 六段：何时用、输入、步骤、输出、检查清单、反例 |
| S09 | skill-maintain | 技能会过时 | 定期复查、合并、删除；技能架季度盘点 |
| S10 | close | 一次投入，长期省 | 建工作区、写记忆、沉淀技能三步行动卡 |

- **交付物**：真实项目工作区 + AGENTS.md（四块）+ 第一个 Skill（SKILL.md）并跑一次验证。
- **风险**：AGENTS.md 支持名单与 Skill 格式随 Harness 变化，只讲通用结构；不把具体工具的私有路径写成标准。
- **优先级**：P1。

## 5. 非编程路线

### 5.1 办公与创作（O1–O5）

定位：只讲「这门活怎么干」，不重讲框架与红线。每门课从真实交付物（周报、汇报、客户方案、清洗后的表、调研 memo）进出口，每屏一个点，不评工具优劣、不写价格。练习素材全部虚构或脱敏，界面用自绘复刻或脱敏截图。

#### O1 · 用 AI 做一份能讲的 PPT

- **定位**：把明早要讲的汇报从空白页做成十页有结论、有证据、讲得出口的 PPT。
- **受众与前置**：常做汇报但非设计岗，会套模板不会排版；已完成 F1–F3。
- **学完能**：① 用一句话结论定骨架；② 把初稿改成一页一观点的可讲稿；③ 用检查单核对数字、页数和时长。
- **场景（9 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 明早的空白页 | 汇报前夜，空白 PPT 光标在闪；先想清要谁做什么决定 |
| S02 | decision | 先写一句话 | 全篇一个结论；结论句拆成三条论据；没结论的 PPT 是资料搬运 |
| S03 | outline | 页数由时间定 | 按听众时长搭骨架，十页删到八页；十分钟只配八页 |
| S04 | draft | AI 只出毛坯 | 初稿省掉空白页，标红六成待改；初稿别当成品交付 |
| S05 | oneidea | 标题即结论 | 标题写成判断句；「销售情况」改成「Q3 靠华东回款翻正」 |
| S06 | source | 数字有出处 | 图旁挂来源标签；追不到源表的数不进 PPT |
| S07 | layout | 版式服务阅读 | 一屏一重点，改版前后对照；清楚优先于漂亮 |
| S08 | notes | 备注是提词器 | 三句提示加停顿标记；眼睛看听众不看字 |
| S09 | check | 会前十分钟 | 检查单打勾并计时彩排；讲超时比讲不好更常见 |

- **交付物**：一页 PPT 骨架模板（结论句 + 每页标题）+ 会前六项检查单；静态直链分发，不需要平台能力。
- **风险**：PPT 工具界面与一键成稿能力变化快，只演示通用操作。
- **优先级**：P0（办公线入口）。

#### O2 · 用 AI 写文档、邮件与汇报

- **定位**：同一份内容写成老板要的汇报、客户要的方案、同事要的邮件，每种都对路。
- **受众与前置**：每天写字、常被退改；不要求文笔好；已完成 F1–F3。
- **学完能**：① 按读者与目的选文体；② 把纪要变成带责任人和时间的行动项；③ 改掉 AI 腔，发出前核对事实与承诺。
- **场景（9 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 同一件事三种写法 | 三种写法并排；先问写给谁、要他做什么 |
| S02 | reader | 先定读者与目的 | 谁、要什么、多久，一张便签定结构语气 |
| S03 | minutes | 纪要只留行动项 | 速记稿删到三行行动项；没责任人和时间的纪要等于没开 |
| S04 | weekly | 周报不写流水账 | 结果、风险、下周计划；老板只看能否帮他决策 |
| S05 | proposal | 先讲客户的问题 | 用客户语言写价值；先复述问题再给方案 |
| S06 | report | 汇报结论先行 | 结论、证据、建议三页骨架 |
| S07 | rewrite | 删掉 AI 腔 | 「赋能、闭环、抓手」逐个替换成具体名词和动词 |
| S08 | tone | 语气是关系管理 | 对上、对客户、对同事，同一句话三种版本 |
| S09 | check | 发出前四查 | 事实、数字、承诺、口径；发出去的字收不回来 |

- **交付物**：会议纪要模板（行动项三列 + 决议）+ 周报三段式模板 + 改稿十问。
- **风险**：企业文体偏好差异大，模板标「可改」；案例用虚构公司。
- **优先级**：P0。

#### O3 · 用 AI 处理表格与数据

- **定位**：把两千行销售表变成一张交代得清的汇总表，每个数都能对上源数据。
- **受众与前置**：会用表格填数，不会复杂公式；已完成 F1–F3。
- **学完能**：① 把表整理成一行一条记录的干净结构；② 让 AI 写公式、做透视并按口径复核；③ 交出一页结论加底表，抽样可追。
- **场景（9 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 周五要交的两千行 | 合并单元格、空值、单位混用；先认清结构再让 AI 动手 |
| S02 | structure | 一行一条记录 | 脏表拆成字段列；表头一列一个字段 |
| S03 | ask | 把「帮我分析」说清楚 | 模糊需求改成字段、口径、输出三行任务卡 |
| S04 | clean | 清洗四件事 | 去重、空值、格式、单位；日期三种写法被统一 |
| S05 | formula | 让 AI 写公式 | 公式与解释一起给，会读公式才敢信结果 |
| S06 | pivot | 透视按口径汇总 | 按区域乘月份拖出汇总；口径不同结论能相反 |
| S07 | chart | 图选错会骗人 | 折线看趋势、柱状比大小，同一组数三种图对比 |
| S08 | verify | 抽样对源表 | AI 算错不罕见；交之前至少手工核对十行 |
| S09 | deliver | 一页结论加底表 | 结论可读、底表可查；每个数都要答得出哪来的 |

- **交付物**：脱敏练习表（200 行销售数据，含脏数据与期望答案）+ 交表前自查表。
- **风险**：函数与版本绑定，要给替代写法；练习数据全部虚构。
- **优先级**：P0（办公三件套之一）。

#### O4 · 用 AI 做调研与判断

- **定位**：三天摸清一个市场或竞品，给老板一页有证据、有不确定性、能拍板的调研 memo。
- **受众与前置**：要做行业或竞品调研，不熟检索与验证；已完成 F1–F3。
- **学完能**：① 把「摸清市场」拆成可查子问题；② 同一事实用两个独立来源交叉验证，标口径和日期；③ 写出一页含不确定性的可决策结论。
- **场景（9 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 老板的三天期限 | 调研先定要拍什么板；没有决策问题的调研会跑偏 |
| S02 | question | 先写决策问题 | 谁、决定什么、够用标准；问题不对答案再全也没用 |
| S03 | split | 拆成可查子问题 | 市场、客户、竞品、渠道四象限，每块只留三个必答问题 |
| S04 | sources | 分清一手与二手 | 官网、招标、财报 vs 报告、媒体；二手结论要回到一手数据 |
| S05 | cross | 同一事实两个来源 | 看日期与统计口径；两份冲突数据并排标红 |
| S06 | slop | 识别人造引用 | AI 会编报告名和数字；查不到原文的引用一律不用 |
| S07 | compare | 竞品用同一张表 | 功能、价格、客户、渠道四维表；维度不统一比较就是广告 |
| S08 | conclusion | 结论带不确定性 | 分已证实、待验证、假设三档 |
| S09 | deliver | 一页调研 memo | 结论、证据、风险、下一步；终点是建议不是资料堆 |

- **交付物**：一页调研 memo 模板 + 来源可信度评分卡 + 三份模拟来源包。
- **风险**：市场规模口径不一、每年更新，只给方法不写死数字；示例只用模拟来源。
- **优先级**：P1。

#### O5 · 用 AI 做图、视频与声音

- **定位**：为培训材料、公众号、客户提案做出能用的图、片头和配音：先过规格与版权，再谈好看。
- **受众与前置**：要做宣传物料但非设计剪辑岗；已完成 F1–F3。
- **学完能**：① 先定用途、尺寸和时长；② 用主体、景别、光线这类画面语言提需求；③ 交付前过一遍文字、版权和平台适配。
- **场景（8 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 培训材料缺图缺片头 | 课件里三处空白占位框；先定用途再决定做什么 |
| S02 | spec | 规格先行 | 尺寸、时长、字幕、平台；16:9 与 1:1 两套画布对照 |
| S03 | shot | 用镜头语言提需求 | 主体、景别、光线、环境；说画面不说形容词 |
| S04 | consistent | 多张图要像一套 | 风格锚点贯穿；一致性优先于单张惊艳 |
| S05 | legal | 版权与肖像 | 商用、商标、真人肖像；拿不准的素材不用 |
| S06 | voice | 配音先听语速 | 断句、重音、情绪；先做十五秒试听再录全长 |
| S07 | video | 片头是分镜拼的 | 三十秒片头拆成五格分镜，每格只做一件事 |
| S08 | check | 发布前四查 | 文字、水印、尺寸、字幕；生成物里的字十有八九要改 |

- **交付物**：30 秒片头分镜表 + 三张封面小样 + 发布前检查单。
- **风险**：生成模型能力、价格、版权政策与平台水印规则变动极快，最易过时，放 P2。
- **优先级**：P2。

### 5.2 零代码构建（W1–W4）

路线定位：**不教语法，教「把东西做出来并验收」**。四门课共用一条非语法骨架：提需求（需求四件套）→ 让 AI 做（一次给完整可运行的东西）→ 验收（打开、点、对清单）→ 排错（现象 + 报错 + 刚做了什么，一次只改一处）。每门课以一个「能发给别人」的成果收尾。与编程员路线的分界：本系列不教语言、框架、工程化和测试体系，只教协作、验收与排错。

#### W1 · 零基础做第一个网页

- **定位**：用 3 轮对话把一句话变成能发给别人的网页链接。
- **前置**：无硬前置；会用浏览器和复制粘贴即可。
- **学完能**：① 用「需求四件套」让 AI 生成完整单文件网页并打开；② 每轮只改一处，指着具体元素提修改；③ 发布成公网链接并按 5 条清单自检。
- **场景（10 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 一句话，一个链接 | 一句话变页面再变手机上的网址；课末你有一个自己的链接 |
| S02 | three-parts | 网页就是三样东西 | 内容、样子、动作三张卡被对话框装配；不用背语法，只要知道让 AI 改哪样 |
| S03 | brief | 需求四件套 | 给谁看、放什么、什么风格、交付成什么；对比反例「做个网站」 |
| S04 | generate | 一次生成完整页面 | 对话框 → 存 index.html → 双击打开；先要能跑，再谈好看 |
| S05 | iterate | 第 2 轮：指着改 | 左页面右对话，一轮只改字号或颜色；具体到元素和数值才听话 |
| S06 | read-code | 只认三个区 | head、正文、style 各管什么；懂用途即可 |
| S07 | white-screen | 白屏急救 | 存成 .txt、标签没闭合、乱码三连修；把浏览器现象原样贴给 AI |
| S08 | publish | 本地文件变网址 | GitHub Pages 或 Netlify Drop，手机扫码打开；有链接才算交付 |
| S09 | checklist | 发出去前的 5 条自检 | 能打开、手机不溢出、无占位文案、链接可点、别人能开 |
| S10 | closing | 你学会的是循环 | 需求→生成→验收→排错四拍循环；下一课让页面活起来 |

- **交付物/验收**：单文件网页（个人主页/活动页/小组介绍三选一）+ 公网 URL；桌面与手机宽度无横向溢出，无占位文字，发给朋友能独立打开。
- **常见翻车点**：输出被截断、存错后缀、一轮提五个改动、只说「丑」不说改哪、Pages 分支选错。
- **优先级**：P0（零代码路线入口）。

#### W2 · 让网页有交互和数据

- **定位**：给静态页装上「能点、能填、能记住」，并知道数据存在哪。
- **前置**：W1，已有可发布的静态页。
- **学完能**：① 把「点了会怎样」翻译成「事件 → 动作 → 状态」三件套需求；② 让 AI 加表单、按钮和本地存储，并说清「刷新还在、换设备没有」；③ 打开控制台，用「现象 + 报错 + 刚做了什么」定位问题。
- **场景（11 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 同一张页，加个「会用」 | 静态页与能点能存的页并排 |
| S02 | model | 交互三件套 | 事件、动作、状态一条流水线；照三件套提需求不会漏 |
| S03 | form | 表单收输入 | 三字段报名表单 + 提交与提示；表单是最便宜的用户输入 |
| S04 | event | 点了会怎样 | 防重复提交、空输入提示、按钮禁用；把出错时怎么办一起提 |
| S05 | storage | 数据放哪：本地存储 | 草稿刷新还在、换设备就没了；先问数据给谁看，再决定放哪 |
| S06 | devtools | 打开看不见的后台 | F12 的 Console 看报错、Application 看键值；白屏先看控制台 |
| S07 | json | 看懂数据信封 | 把返回数据拆成字段名和值；能指认字段就行 |
| S08 | api | 调接口：门禁与失败 | key 不能写进前端；401、429、网络错误分别怎么办 |
| S09 | boundary | 再发布：部署与边界 | 文件在云端、数据在用户浏览器；要所有人看同一份数据，就需要后端 |
| S10 | verify | 验收：点完所有路径 | 空表单、超长输入、刷新、手机逐条过 |
| S11 | closing | 下一课：把重复交出去 | 下一课让 AI 写脚本 |

- **交付物/验收**：报名/记账/打卡小页面：有表单、提交后即时更新、刷新还在、有清空按钮；空表单不崩、数据持久、手机可操作。
- **常见翻车点**：少了阻止默认提交、对象没转 JSON、把 API key 写进前端、把额度/CORS 失败当代码 bug。
- **优先级**：P1。

#### W3 · 用 AI 写小工具与自动化脚本

- **定位**：把每周重复的复制粘贴，交给一个写一次、跑很多次的脚本。
- **前置**：能用桌面 AI 工具或命令行 Agent；W1/W2 不是必须。
- **学完能**：① 判断哪些重复劳动值得写成脚本，并说清输入、处理、输出；② 让 AI 生成并运行脚本，出错时贴对信息；③ 守住安全边界：先备份、先小样本、不给密钥、看不懂的命令不跑。
- **场景（11 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 每周一小时，脚本三秒 | 批量改名、批量压图、汇总日报三例并排 |
| S02 | what | 写一次，跑很多次 | 手工一列对比一条流水线；网页给人看、脚本给电脑跑 |
| S03 | cli | 终端只学三个动作 | 打开、cd 到文件夹、粘贴运行；其余标灰 |
| S04 | agent | 把文件夹交给 Agent | 桌面/命令行 Agent 能读写文件、跑命令；你负责划边界 |
| S05 | brief | 需求四件套 | 输入在哪、做什么、输出到哪、失败怎么办；例：合并发票 PDF 不动原件 |
| S06 | error | 报错是线索 | 只看最后两行和退出码；贴着报错问，快十倍 |
| S07 | small-steps | 一个，十个，全部 | dry-run、先复制、输出加版本号；能撤回才敢放大 |
| S08 | safety | 三条红线 | 不给密钥、不跑看不懂的一键命令、不传公司文件到未知服务 |
| S09 | routine | 变成习惯 | 定时或每次开工前自动跑，结果写到固定目录 |
| S10 | checklist | 脚本的 4 条自检 | 原件没动、输出在对处、失败有日志、别人能跑 |
| S11 | closing | 你有了一个自动化工人 | 下一步把它变成别人能用的产品 |

- **交付物/验收**：一个真实跑通的脚本 + 3 行 README（怎么跑、输入在哪、输出在哪）+ 备份说明；连跑两次结果一致、原件未改、给错路径有可读报错。
- **常见翻车点**：在错误目录执行删错文件、路径带空格/中文没加引号、AI 说装好了其实缺依赖、照抄看不懂的命令、把密钥贴进对话。
- **优先级**：P1（可独立上线，对办公人群价值最高）。

#### W4 · 从想法到上线：做一个能用的产品

- **定位**：capstone：把一个真实小想法走完五步，变成有链接、别人能用的产品。
- **前置**：W1、W2；想解决一个自己的真实小需求。
- **学完能**：① 把模糊想法收敛成一个用户、一个场景、一个核心流程，写出可验收的完成定义；② 按原型、计划、分步实现、自测、发布走完，每步有验收再进下一步；③ 上线后收反馈、留回滚、守住范围，做 1.1 不做 3.0。
- **场景（12 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 一个小真需求 | 三人排班合成一张手机能看的表；小产品也一样要走五步 |
| S02 | one-liner | 想法变一句话 | 反例「做个 AI 工具」对比「给小组做共享值日表」 |
| S03 | scope | 砍到 1.0 | 愿望清单剪到 3 项；MVP 是一条能跑通的最小路径 |
| S04 | dod | 先写验收单 | 能打开、流程通、手机能用、错误有提示、别人能自用 |
| S05 | prototype | 先原型 15 分钟 | 手绘线框或 AI 静态页，先定信息与流程；改原型最便宜 |
| S06 | plan | 先要计划再要代码 | 分三步，每步交付什么、怎么验证，拒绝一次全给 |
| S07 | build | 分步实现 | 数据写死 → 加增删 → 本地保存，每步验收 |
| S08 | test | 自己当测试 | 正常、错误输入、空状态三条路，记录现象和步骤 |
| S09 | user-test | 找真人试 5 分钟 | 不解释，只看他卡在哪，收 3 条观察 |
| S10 | ship | 上线与兜底 | 发布、留上一版可回滚；坏了先回滚再修 |
| S11 | after | 1.0 之后 | 按用的人多、坏得多、改得快排 1.1，守住范围 |
| S12 | closing | 走完一遍完整循环 | 五步循环 + 你的产品链接；学会的是把想法做完并交付 |

- **交付物/验收**：单页小产品（能增删数据、刷新还在、手机可用、有链接）+ 一页 README + 1 条真人试用记录；完成定义 5 条逐条打勾，做一次回滚演练。
- **常见翻车点**：范围膨胀、只测正常路径、AI 重写吃掉已通过功能、没有备份回滚、最后才想手机适配、把真实客户数据写进页面。
- **优先级**：P2（路线收口，单课成本最高但最出成果）。

### 5.3 自动化与个人 Agent（A1–A2）

#### A1 · 把重复工作交给 AI：工作流与定时自动化

- **定位**：把每周固定要做的汇总、分发、提醒交给一条可视化流程，人只处理例外。
- **受众与前置**：每周有固定重复活、不写代码；已完成基础必修。
- **学完能**：① 判断一件事值不值得自动化；② 用触发器、步骤、变量、分支、审批拼出一条流程；③ 用样例试跑、处理异常，上线后看运行记录。
- **场景（9 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 每周一上午的固定活 | 日历上周一被占死两小时；自动化省的不只是时间 |
| S02 | judge | 先判断值不值得 | 高频、规则清、输入输出固定；偶发且靠判断的活别自动化 |
| S03 | trigger | 触发器决定何时跑 | 定时与事件两类；先问「什么时候该跑」 |
| S04 | steps | 步骤是一条流水线 | 取数、处理、产出、发送；一步只做一件事，出错好查 |
| S05 | variable | 变量与模板 | 固定格式加变的数；模板写死，数据留空 |
| S06 | branch | 判断分支转人工 | 条件不满足交给人；别让流程替你做决定 |
| S07 | human | 审批与兜底 | 人审、重试、告警；出问题要有人知道 |
| S08 | test | 先用样例跑一遍 | 试运行、对数、边界样例；拿旧结果对一遍 |
| S09 | monitor | 上线只是开始 | 日志、告警、版本、成本；每天看一眼运行记录 |

- **交付物**：周报自动汇总流程卡（触发器、步骤、变量、分支、审批、兜底）+ 试运行检查表。真实搭建需第三方工作流平台账号；本站只发流程卡。
- **风险**：平台界面、节点命名、额度与价格变动快，只用通用词；案例全部虚构。
- **优先级**：P2。

#### A2 · 搭一个自己的 Agent（非编程）

- **定位**：给自己搭一个只干一类活的小助手：职责、资料、工具、权限、测试，五样配齐才好用。
- **受众与前置**：学完第一课想动手搭一个；不写代码，能接受在平台里点选配置。
- **学完能**：① 写清一个 Agent 的职责与边界；② 配好指令、知识库、工具与最小权限；③ 用真实问题测出失败模式并定好兜底。
- **场景（10 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 每天都在回答同一类问题 | 聊天记录里同一问题问五遍；先把「只干一类活」说清楚 |
| S02 | job | 一句话职责 | 职责卡：服务谁、解决什么、不做什么；边界比能力更决定好不好用 |
| S03 | instruction | 指令写规则 | 输入、步骤、输出、禁区；能检查的规则才是规则 |
| S04 | knowledge | 知识库喂什么 | 选资料、切分、更新、失效；知识库不是网盘，过期要下架 |
| S05 | tools | 给它工具才有用 | 查表、发消息、检索；每加一个工具多一分风险 |
| S06 | permission | 权限分三级 | 只读、可写、须人确认；能自动做的事越少越敢用 |
| S07 | test | 用十个真问题测 | 覆盖常见与边界；没测过的 Agent 不能上岗 |
| S08 | failure | 失败模式与兜底 | 编造、越权、答非所问，四种失败各配兜底话术 |
| S09 | operate | 上线与迭代 | 日志、反馈、版本、成本；每天看它错在哪比加功能有用 |
| S10 | deliver | 交出自己的 Agent | 设计卡六栏填满；能维护的 Agent 才算搭完 |

- **交付物**：Agent 设计卡（职责、指令、知识库清单、工具与权限、十道测试题、兜底话术）+ 上线两周观察表。真实搭建需第三方平台账号。
- **风险**：各平台对知识库、工具、权限的实现差异大，按通用五件套讲；功能与额度变动快；测评素材必须脱敏。
- **优先级**：P1。

## 6. 编程员路线

### 6.1 AI 辅助编程基础（D1–D5）

这一组给有 1 年以上项目经验、日常用 git 与终端的开发者。不教语法与框架，只讲 AI 协作的工作流、验证与风险控制。统一结构：反直觉 Hook → 分清形态 → 工作流（代码或终端演示）→ 验证与风险 → 收尾。练习在学员自己的仓库做，课内只给模板、命令与验收清单。

#### D1 · AI 编程入门：从补全到 Agent

- **定位**：把 AI 编程从「随手问问」变成按任务选入口、按风险设边界的日常工具。
- **受众与前置**：知道 Agent 会读文件、跑命令（第一课 S09–S13）。
- **学完能**：① 用「可验证、影响面、上下文」三问给任务分级，选补全、对话还是 Agent；② 在 IDE、CLI、云端三种入口里按任务选一个并说出理由；③ 列出三类不该交给 Agent 的工作与替代做法。
- **场景（9 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 一天四种活 | 补全、问 API、加导出、排 500；选错入口最费时间 |
| S02 | three-forms | 三种形态 | 同一「加缓存」：补全猜下一行、对话靠你搬上下文、Agent 读文件跑测试 |
| S03 | grading | 任务三问 | 可验证、影响面、上下文；三问都过才交给 Agent 自主跑 |
| S04 | ide | 看得见 diff | 补全加多文件 diff，逐条 accept / reject；IDE 强在改动可见、随时打断 |
| S05 | cli | 验证进循环 | 改 3 个文件 → pytest 失败 → 读报错再改 → 通过 → git diff --stat |
| S06 | cloud | 排队验收 | issue 写清验收标准，远端开分支跑 CI 出 PR；适合边界清楚、可远程验收 |
| S07 | not-agent | 什么时候别用 | 改密钥权限、无测试热修、逐行解释的合规代码、一次性探索 |
| S08 | rework | 返工账 | 同一任务，「加个导出」vs 带验收标准的说明，比改动量与返工 |
| S09 | close | 今天三件事 | AGENTS.md 补三条约束、下个任务先分级、每个 diff 必看 |

- **练习/验收**：挑 3 个真实任务，分别用补全、对话、Agent 做一次，记录入口、耗时、返工；三行对照卡写清为何不用另外两种入口。
- **常见误区**：把 Agent 当补全用；没写验收标准就放手；diff 不看直接合；把更强模型当任务定义的替代品。
- **风险**：产品形态与按钮月月变，只讲 IDE / CLI / 云端；不排名、不写「生成了多少代码」。
- **优先级**：P0。

#### D2 · 先想清楚再动手：需求澄清、规格与计划

- **定位**：把「帮我做 X」变成一份能验收的 spec 和可回滚的任务序列，再让 Agent 动手。
- **受众与前置**：D1；会写 issue 或需求文档更好。
- **学完能**：① 用六问把模糊需求盘成可验收需求；② 写一页含范围、非目标、验收标准的 spec；③ 把 spec 拆成每步可单独验证的任务，在 plan 模式里先审后做。
- **场景（10 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 同一需求两次交付 | 「加个 CSV 导出」模糊版 vs spec 版；返工多半是验收标准没定义 |
| S02 | clarify | 盘问六问 | 谁用、什么算完成、不做什么、数据多大、出错怎么办、不能动什么 |
| S03 | spec | spec 五块 | 背景、范围、非目标、验收标准、风险；价值一半在非目标与验收两栏 |
| S04 | acceptance | 可执行验收 | 「看起来对」改成命令、预期输出、空表处理、权限 |
| S05 | plan | 先审后做 | 只读探索 → 写计划 → 人审 → 才允许写；plan 模式买到「改文件之前就能否决」 |
| S06 | split | 拆任务 | 单个可验证、依赖有序、失败可回滚；拆成 5 个 PR 大小的任务 |
| S07 | context | 喂对上下文 | spec、相关文件、AGENTS.md 片段，不是整仓 |
| S08 | interrupt | 何时打断 | 计划偏航、出现新约束、连续两次失败；便宜时打断比贵时回滚划算 |
| S09 | verify | 交付验收 | 跑测试、看 diff、对验收标准逐条打勾 |
| S10 | handoff | 收尾交接 | 拍板的决定写回 spec 与 AGENTS.md，给下个任务留 handoff |

- **练习/验收**：选一个真实需求，写一页 spec（3 条非目标、至少 3 条可执行验收），拆成 ≤5 个任务，用 plan 模式审一遍。验收：同事只看 spec 就能验收；计划至少被改过一次。
- **常见误区**：把 spec 写成 PRD 长文；跳过非目标；验收标准写成形容词；拆成 20 个微步骤。
- **风险**：plan 模式与斜杠命令的边界因产品而异（第一课 S25）；验收命令用通用工具并标注可替换。
- **优先级**：P0。

#### D3 · 调试与排错：把报错变成线索

- **定位**：把「贴报错等答案」改成可复现、可证伪的流程：先复现，再提假设，再实验证伪。
- **受众与前置**：D1；会看堆栈、会用日志和调试器。
- **学完能**：① 产出稳定复现的最小用例；② 让 AI 基于证据提出可证伪假设并设计单变量实验；③ 用二分、日志、快照把范围缩到一处，并留下先红后绿的回归测试。
- **场景（10 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 贴日志对复现 | 偶发空文件 bug，两种求助比回复质量；排错质量取决于证据不是噪音 |
| S02 | reproduce | 最小复现 | 固定环境、输入、步骤、期望，30 行脚本稳定复现 |
| S03 | stack | 读堆栈 | 从最后一行报错倒回第一个自己代码的帧，三层调用定位 |
| S04 | evidence | 证据三件套 | 完整报错、相关代码、最近改动；git log -3 --stat 找嫌疑 |
| S05 | hypotheses | 让 AI 提假设 | 列 3 个假设、各自证据、证伪方法；一条日志否掉一个 |
| S06 | experiment | 一次一个变量 | 加日志、加断言、缩短路径；同时改两处结论作废 |
| S07 | bisect | 二分 | git bisect、注释一半、输入二分；32 次提交 5 步定位 |
| S08 | stall | 卡住换层级 | 两次同类失败就换日志、换输入、换环境、换人 |
| S09 | fix | 修复加回归 | 让 AI 先写会失败的测试再修，红灯到绿灯 |
| S10 | postmortem | 复盘回写 | bug 变成 AGENTS.md 护栏和一条测试 |

- **练习/验收**：拿最近一个 bug 按「复现 → 证据 → 3 假设 → 单变量实验 → 先红后绿」重走一遍；复现脚本可重复跑通，测试先红后绿，复盘补进 AGENTS.md。
- **常见误区**：贴整段日志求答案；一次改多个变量；把 AI 猜测当结论；修完不写测试；同一个问题原样重试三次。
- **风险**：方法长期稳定，AI 读日志能力取决于权限与产品；示例堆栈用真实格式、虚构项目。
- **优先级**：P1。

#### D4 · 测试与代码评审：让 AI 当审稿人

- **定位**：用 AI 扩大测试与评审的覆盖面，但把「通过」的决定权交给可执行的检查。
- **受众与前置**：D1；团队里有 code review 和 CI 流程。
- **学完能**：① 先列风险再让 AI 生成单测，覆盖边界与失败路径；② 识别假测试与覆盖率陷阱；③ 用固定清单审 diff、按风险分级，并把重复问题变成 CI 检查。
- **场景（10 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 同一 PR 两种评审 | 随手读一遍 vs 清单 + AI 复审 + 测试，看漏掉的空指针 |
| S02 | test-design | 先列风险清单 | 边界、失败路径、权限、并发、兼容；先列该测什么再生成测试 |
| S03 | boundary | 边界用例 | 空、超长、0、负数、时区、编码、重复提交，参数化生成 |
| S04 | fake-tests | 假测试识别 | 断言恒真、只测 mock、快照过大、skip 用例 |
| S05 | coverage | 覆盖率用法 | 看未覆盖分支，不追百分比；覆盖率是找盲区的地图 |
| S06 | checklist | 评审清单 | 行为变化、错误处理、边界、安全、性能、可读性、测试 |
| S07 | diff-review | AI 审 diff | 角色是审稿人，范围是本 diff，输出分级问题加证据 |
| S08 | risk-grade | 风险分级 | 丢数据、宕机、泄露必须拦；逻辑错误次之；风格最后 |
| S09 | limits | AI 评审的盲区 | 业务语义、上下文缺失、讨好倾向；AI 扩大覆盖，不替你判断 |
| S10 | gate | 把问题变成门 | 重复出现的问题写进测试、lint、CI、AGENTS.md |

- **练习/验收**：挑一个自己的 PR，先列风险清单、让 AI 补边界测试，再用清单做一轮 AI 复审；找出或排除至少一个真实风险，P0/P1 有处理或明确延期理由。
- **常见误区**：只看覆盖率数字；让 AI 写测试但不审测试；AI 评审代替人工判断；评审意见没落地成检查。
- **风险**：覆盖率口径因工具而异；AI 评审质量随上下文与模型版本变化，不给「能发现 x%」的数字。
- **优先级**：P1。

#### D5 · 重构与遗留代码：读懂旧项目再动刀

- **定位**：先用 AI 画出旧项目的架构地图、锁住行为，再以小步、可回滚、可回归的方式换掉它。
- **受众与前置**：D1、D2；建议先看 D4。
- **学完能**：① 产出旧项目的架构地图与依赖风险清单；② 用行为快照把现状锁住；③ 执行一次三步渐进重构，每步可回滚且回归通过。
- **场景（11 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 大爆炸 vs 渐进 | 重写与重构的进度、风险两条曲线；风险不是丑，是行为没被锁住 |
| S02 | map | 架构地图 | 入口、模块、数据流、外部依赖、定时任务；AI 扫仓库出初稿 |
| S03 | deps | 影响面 | 谁调用它、它调用谁、什么一起变；改前先知道爆炸半径 |
| S04 | behavior | 行为快照 | 特征测试、录输入输出与日志；没有快照，重构就是拿生产做实验 |
| S05 | seams | 找接缝 | 测试接缝、接口边界、开关、可注入点；从接缝进，不从文件中间进 |
| S06 | strangle | 新旧并存 | 绞杀者模式、按流量切换、随时可退 |
| S07 | small-steps | 小步提交 | 每步可构建、可测试、可回滚；大 diff 拆成 6 个 commit |
| S08 | ai-loop | AI 在循环里 | 读 → 建议 → 改一处 → 跑回归 → 记录，一次只做一步 |
| S09 | traps | 四个陷阱 | 顺手改行为、顺手升依赖、大 diff、只跑单测 |
| S10 | regression | 回归验证 | 单测、集成、关键路径冒烟、新旧对比；每步跑同一条回归命令 |
| S11 | close | 收尾 | 删旧路径、更新 AGENTS.md 与文档、复盘；完成标志是旧路径消失 |

- **练习/验收**：选一个带测试的旧模块，做三步渐进重构并保留旧路径开关；每步一个独立 commit 且可回滚，回归全绿，旧路径删除或写明下线条件。
- **常见误区**：先重写再理解；大 diff 一次合；只跑单测；顺手升依赖；旧路径注释不删；没有行为快照就动刀。
- **风险**：框架与工具会变，课程用语言无关描述；绞杀者模式引用 Fowler，来源进讲义。
- **优先级**：P2。

### 6.2 上下文与工具链（D6–D8）

这一组从「一个人会用」进到「项目、团队、产品怎么建」。第一课 S17–S27 只讲了概念与个人习惯，这里每一条都落到可执行、可维护、可审计。

#### D6 · 项目记忆进阶：AGENTS.md 与文档地图

- **定位**：把 AGENTS.md 从一份说明升级成分层、跨工具、可维护的项目记忆系统。
- **受众与前置**：已在真实仓库用 Agent 的开发者/组长；前置 D1。
- **学完能**：① 设计全局、仓库根、子目录、任务四层记忆并定优先级；② 一份源头同步多个工具，不写四份；③ 用三个测试维护文档地图。
- **场景（10 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 三次踩同一个坑 | 三个会话犯同一个错；重复解释是记忆没写对地方的症状 |
| S02 | layers | 记忆分四层 | 全局、根、子目录、任务临时，越具体越小 |
| S03 | root | 根文件只放开工必读 | 目标、命令、禁区、文档地图索引；反面是第二份 README |
| S04 | nested | 子目录覆盖 | monorepo 三份级联，最近优先；冲突谁赢要写清 |
| S05 | compat | 一套源头多工具 | AGENTS.md 为主，其余工具文件脚本生成，不手抄四份 |
| S06 | map | 文档地图 | 三列：症状、读哪份、谁负责；不是文件清单 |
| S07 | include | 引用与去重 | 命令、schema、长文档用指针；三处复制必漂移 |
| S08 | budget | 体积预算 | 记忆每次请求都带上，按省下的解释排序，砍不常读段 |
| S09 | maintain | 把踩坑变规则 | 犯错后补一条，带 owner 与复审日期；PR 加「是否更新」 |
| S10 | gate | 三个测试与收尾 | 新人测试、删除测试、冲突测试；记忆是代码，要 review、要迭代 |

- **交付物**：三层 AGENTS.md（根不超过 60 行）+ 多工具同步脚本；验收：新会话问「这个目录怎么跑测试」能一次答对。
- **风险**：工具支持名单、嵌套优先级、导入语法变化快，开课前实测。
- **优先级**：P1。

#### D7 · 给 Agent 造工具：写 Skill 与 MCP 服务

- **定位**：从「装别人的技能」到「自己造、测、发、管」，把团队流程固化成 Agent 能可靠调用的工具。
- **受众与前置**：有 API 或后端经验的开发者；前置 D6。
- **学完能**：① 写能被正确触发的 SKILL.md；② 把团队流程做成可测试的 MCP server；③ 做正常、边界、危险动作三类测试并定版本与下线。
- **场景（10 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 装上就灵的幻觉 | 两个技能对照：描述含糊的误触发，描述清晰的稳定命中 |
| S02 | form | 先选形态 | 提示、Skill、MCP 三选一决策树：要不要真实副作用 |
| S03 | anat | SKILL.md 解剖 | frontmatter 写何时用，正文写步骤、脚本、输出、自检 |
| S04 | load | 渐进加载 | 目录只放一句描述，正文按需读；参考进 references，代码进 scripts |
| S05 | script | 确定性交给脚本 | 能让 shell 算的别让模型算；脚本幂等、有 dry-run、可解析 |
| S06 | mcp | MCP 三角 | Host、Client、Server 与 tools/resources/prompts 的边界 |
| S07 | schema | schema 设计 | 参数少而正交，写清何时别用；结构化错误代替抛异常 |
| S08 | perm | 权限与凭据 | 只读优先、按目录授权、危险动作确认；凭据从环境注入 |
| S09 | test | 三类测试 | 正常、边界、危险动作；录制回放代替真实调用 |
| S10 | ship | 版本维护与收尾 | 一技能一目录、版本、变更记录、owner 与下线；成熟度五级 |

- **交付物**：把一个每次都要口述的团队流程写成 Skill（正文不超过 80 行 + 一个脚本），跑三次真实任务记误触发与漏触发；再写一个只读 MCP server，坏参数、超时、断网三种情况都有明确返回。
- **风险**：MCP 规范版本、传输方式、授权模型变化快，各 Harness 的 Skill 字段要求也不一致；只写能力要求，不写「某工具标准」。
- **优先级**：P2。

#### D8 · 多 Agent 与并行开发

- **定位**：靠任务拆分、写区隔离、审查门禁让多个 Agent 并行，而不是靠更多 Agent。
- **受众与前置**：有代码库协作经验的开发者/组长；前置 D4、D6。
- **学完能**：① 判断任务该不该并行；② 设计规划、执行、审查三角色与独立工作区；③ 给流程设测试、审查、合并门禁并算清收益。
- **场景（10 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 三个 Agent 改同一文件 | 谁先提交谁赢，另外两个白干 |
| S02 | calc | 并行收益账 | 加速约等于可并行部分除以协调成本，画成本曲线 |
| S03 | split | 按写区切 | 按文件、模块、服务切，不按步骤切；共享文件是冲突源 |
| S04 | roles | 三种角色 | 规划、执行、审查；审查者独立上下文，只看 diff 与标准 |
| S05 | iso | 隔离手段 | 一 Agent 一 worktree / 分支 / 容器；谁合并谁负责 |
| S06 | card | 任务卡与回报 | 范围、禁区、验收、依赖四栏；失败也要结构化回报 |
| S07 | board | 防冲突 | 先 claim 后开工、写 scope、共享文件串行、定期 rebase |
| S08 | gate | 审查门禁 | 不信执行者自述；按风险分级，高风险人审，测试不过不合 |
| S09 | ci | CI 与止损 | 每分支同检查、合并队列、失败重跑；设 token、时间、并发上限 |
| S10 | close | 先从只读并行开始 | 先并行两个只读调查，再并行写入；先证明收益再扩大 |

- **交付物**：把真实任务拆成三张任务卡（含写区），开两个 worktree 并行做并按门禁合并，记冲突次数与返工；再写一份多 Agent 运行规约。
- **风险**：各工具的子 Agent、并行与任务板能力差异大且更新快；只写「具备某能力时怎么做」，不点名背书。
- **优先级**：P2。

### 6.3 工程与团队（D9–D11）

#### D9 · AI 编程的安全与工程底线

- **定位**：把「AI 写代码」的风险变成可执行规则：权限、数据、供应链、许可、责任。
- **受众与前置**：所有用 AI 写代码的开发者；前置 D1。第一课 S27 只讲「别贴密钥」，本课讲体系。
- **学完能**：① 设计最小权限且可回滚的 Agent 工作环境；② 拦住 AI 带来的供应链与许可证风险；③ 建立可执行的审查与责任规则。
- **场景（11 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 顺手装个依赖 | AI 建议的包名不存在或被抢注，装进去就跑；安全要人加 |
| S02 | model | 威胁模型 | 五类资产乘四种能力（读、写、执行、联网），画风险矩阵 |
| S03 | perm | 权限分级 | 只读、写工作区、执行、联网、生产凭据，逐级默认关闭 |
| S04 | sandbox | 沙箱 | 容器、临时目录、受限用户；删除与 force push 要拦截或审批 |
| S05 | secrets | 凭据 | 环境变量、密钥管理器、短期令牌；不进提示词、仓库、日志 |
| S06 | data | 数据边界 | 客户数据、个人信息、未公开代码先分级脱敏；留存看合同 |
| S07 | supply | 供应链 | 幻觉依赖、包名抢注、lockfile、安装脚本、CI token 权限 |
| S08 | license | 许可证与来源 | 生成代码的版权状态、copyleft 污染、对外交付声明 |
| S09 | inject | 间接注入 | 仓库文档和 issue 也能指挥 Agent；外部内容当不可信输入 |
| S10 | review | 责任与审计 | 高风险改动必须人审；记录谁让 Agent 做了什么 |
| S11 | close | 六项安全清单 | 环境、凭据、依赖、许可、评审、演练；让 AI 在框里干 |

- **交付物**：给自己的项目做一次 AI 安全体检（权限、凭据、可执行命令、依赖来源、许可证），产出一页清单加三条整改；再写 AI 改动高风险清单接入 PR 模板，用一次真实改动演练审批。
- **风险**：生成物可版权性、AI 法规与判例仍在变；只讲判断框架，不给法律意见。
- **优先级**：P1（程序员第二波尽早）。

#### D10 · 设计一个 AI 应用：RAG、工具调用、评测与成本

- **定位**：给技术负责人一份从 demo 到上线的架构判断：先定评测，再选架构，最后谈成本与降级。
- **受众与前置**：有后端与系统设计经验的技术负责人；前置 D9 + 基本 LLM API 经验。
- **学完能**：① 画出六层架构并说清每层失败模式；② 用 30–100 条评测集决定检索、模型与提示取舍；③ 给延迟、成本、质量定预算与降级，埋好可观测。
- **场景（12 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | demo 上线翻车 | 同一问题三种失败：答错、超时、太贵；质量不是看起来对 |
| S02 | arch | 六层架构 | 入口、编排、检索、模型、工具、可观测；标每层最先坏在哪 |
| S03 | eval | 先建评测集 | 真实问题、期望、失败类型，30 条起步；没评测就没优化方向 |
| S04 | need | 要不要 RAG | 知识不在模型、必须引用、常更新才上检索；通用能力别硬套 |
| S05 | rag | 检索工程 | 切分、混合检索、重排、引用回链，一条流水线 |
| S06 | tool | 工具契约 | schema、幂等、超时、重试、人工确认；错误要能让模型改路线 |
| S07 | judge | 评测方法 | 离线集、线上抽样、人工抽检；LLM 裁判要校准；改提示先回归 |
| S08 | latency | 延迟预算 | 首 token、整段、工具往返逐层分；流式、并行、预取 |
| S09 | cost | 成本预算 | 单价乘调用量，算缓存、分级模型、批处理；算每条请求成本 |
| S10 | degrade | 降级兜底 | 超时走小模型、缓存、人工；检索为空怎么答 |
| S11 | obs | 可观测 | trace、token、失败分类、反馈回流；日志脱敏 |
| S12 | close | 上线检查表 | 评测过、预算明、有降级、有 owner、可回滚；先做薄再做深 |

- **交付物**：一个 AI 功能的架构决策记录（六层、失败模式、预算、降级）+ 30 条评测集，跑纯模型与加 RAG 两个方案，用通过率、延迟、成本三列对比做决定。
- **风险**：模型价格、窗口、能力月月变；不写具体产品评测结论，只讲方法与复核点。
- **优先级**：P2。

#### D11 · 团队怎么用 AI：规范、评审与度量

- **定位**：把个人效率变成团队能力：一份能落地的使用规约、评审政策、知识库与度量。
- **受众与前置**：技术负责人、团队 lead、平台负责人；前置 D6、D9。
- **学完能**：① 写一份团队 AI 使用规约；② 搭团队知识库让经验可复用；③ 设计一套不虚的度量并做 90 天试点。
- **场景（11 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 买了工具没人用 | 三个月后三种死法：没场景、没规矩、没度量 |
| S02 | base | 先量基线 | 周期时间、评审时长、缺陷率、变更失败率；没基线没有 ROI |
| S03 | policy | 规约三张纸 | 能做、不能做、怎么做：场景、数据权限、评审与回滚 |
| S04 | review | 评审政策 | 风险等级决定审查强度，不是 AI 生成比例；高风险人审加双人 |
| S05 | kb | 团队知识库 | AGENTS.md 金字塔、内部 Skill 库、踩坑清单、决策记录，定 owner |
| S06 | onboard | 新人上手 | Day 1 装工具读规约，Week 1 跟一个真实任务；验收会用 |
| S07 | metric | 度量设计 | 领先指标看覆盖与频率，落后指标看周期、质量、成本；别数 LOC |
| S08 | roi | ROI 算法 | 省下工时乘时薪，减工具与评审成本与返工；先算一个场景 |
| S09 | gov | 治理 | 工具采购与标准、统一账号、审计、供应商数据条款、影子 AI |
| S10 | rollout | 90 天落地 | 试点、量基线、迭代规约、推广；写清失败信号与止损 |
| S11 | close | 一页团队 AI 手册 | 目录加三个动作：写规约、建知识库、跑试点；收益在流程不在工具 |

- **交付物**：团队 AI 使用规约（场景、禁区、评审、责任）试运行一个迭代并收 5 条反馈 + 一个重复场景的 30 天试点复盘（基线、AI 流程、ROI、继续/调整/停止）。
- **风险**：劳动、隐私、行业监管与供应商数据条款因公司和国家而异；不给通用法律与人事建议，ROI 数字标注假设。
- **优先级**：P2。

## 7. 达人合流

这一层不教新概念，只做三件事：把零件组装成一个作品、把工具变成系统、把「跟上变化」变成习惯。

### X1 · 从需求到上线：做一个会干活的 Agent

- **定位**：项目课。非编程学员用可视化平台，程序员用 Agent CLI/IDE，两条路径共用同一套项目方法。
- **前置**：走完任一路线到 L3（W2/W3 或 D3/D4）；看过第一课。
- **学完能**：
  1. 把一个模糊需求写成可验收的 Agent 方案（目标、输入输出、工具、权限、失败兜底）。
  2. 用无代码平台或代码方式搭出一个能运行的 Agent/工作流，并给它写项目记忆与技能。
  3. 用测试用例和日志验收，说清它什么时候会出错、怎么兜底。
- **场景（12 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 两个翻车现场 | 一个越权删了文件、一个胡编数据，引出「能跑」和「能放心跑」是两件事 |
| S02 | method | 项目六步 | 需求→设计→搭建→测试→上线→复盘，一张图贯穿全课 |
| S03 | requirement | 先把需求写死 | 用「会议纪要助手」示例写目标、输入、输出、成功标准、失败兜底 |
| S04 | choose | 选路线 | 无代码 vs 代码、自建 vs 现成工具、成本估算，三条决策线 |
| S05 | design | 五格设计图 | 指令（系统提示）、知识（素材）、工具（能做什么）、记忆（AGENTS.md）、权限（能碰什么） |
| S06 | build-nocode | 搭演示 A：非编程 | 可视化平台从表单到产出，搭一个「周报生成器」 |
| S07 | build-code | 搭演示 B：编程 | Agent CLI + 目录记忆 + 一个小脚本工具，完成同一件事 |
| S08 | tools | 接真实工具 | 文件、表格、浏览器、消息；MCP 只讲怎么接（原理第一课已讲） |
| S09 | test | 十个用例 | 正常、边界、误用各准备几个，记录通过率；失败长什么样 |
| S10 | guardrail | 红黄绿灯 | 人工确认、只读优先、日志与回滚，按风险等级设权限 |
| S11 | iterate | 上线与迭代 | 收集反馈、改一条规则、把提示词与记忆放进版本管理 |
| S12 | ship | 作品清单 | 交付验收表 + 下一步（去 X2 搭工作系统） |

- **练习/交付物**：一个可运行的 Agent 或工作流 + 一页设计说明 + 10 条测试记录（含 3 条失败）。
- **平台依赖**：练习屏/作品提交（可选）；课程本身可先做成纯旁白课。
- **优先级**：P2。

### X2 · 把 AI 用成工作系统

- **定位**：从单点工具到个人工作系统。适合已经会用 AI、但用得很零散的人。
- **前置**：A2 或 X1，或完成任意 3 门应用课。
- **学完能**：
  1. 设计自己的 AI 工作区（目录约定 + 项目记忆 + 素材区）。
  2. 建一个可检索、可维护的个人知识库。
  3. 把三个重复流程交给 AI，并形成每周复盘的习惯。
- **场景（10 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 工具切换税 | 一天被打断二十次：每换一个工具就重新讲一遍背景 |
| S02 | system | 五件套 | 输入（素材/知识）、记忆（项目/全局）、流程（提示词/技能/工作流）、输出（模板/交付物）、复盘（日志/规则） |
| S03 | folders | 目录即系统 | 一个工作区怎么放素材、草稿、交付物、参考；命名与归档 |
| S04 | memory | 两层记忆 | 项目级 vs 全局：写什么、不写什么、多久维护一次 |
| S05 | knowledge | 从收藏到可检索 | 先目录后检索；知识库和 RAG 的关系一句话讲清 |
| S06 | templates | 模板库 | 把常用提示词、PPT 结构、检查清单做成自己的资产 |
| S07 | automate | 哪些该自动 | 定时任务、监听文件夹、消息提醒；哪些必须人工确认 |
| S08 | review | 每周十分钟 | 哪条规则该加、哪个模板该改、哪个工具该停 |
| S09 | case | 一个人跑完一条链 | 调研→PPT→汇报：看系统怎么把四门课串起来 |
| S10 | start | 本周三件事 | 建 AGENTS.md、收一个模板、自动化一件小事 |

- **练习/交付物**：自己的 AGENTS.md + 模板库清单 + 一条自动化流程。
- **优先级**：P2。

### X3 · AI 月月更新，怎么持续跟上

- **定位**：方法论课。工具会过时，判断力不会。
- **前置**：完成任意 3 门应用课。
- **学完能**：
  1. 建立自己的信息源与筛选标准。
  2. 会做「一周试用」评测，不被发布会和榜单带节奏。
  3. 每季度清理一次工具、技能与订阅。
- **场景（8 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 去年最火的工具 | 今天还在用吗？引出「追新」和「有用」是两回事 |
| S02 | layers | 三层变化 | 模型、产品、工作流，哪一层值得你追 |

- **练习/交付物**：一张自己的「工具雷达」表 + 一次一周试用记录。
- **优先级**：P2。

## 8. 通用能力线（非 AI）

这条线回答用户的要求：交互式课堂不只教 AI。原则是**能力为主、AI 当陪练**：课程主体是写作、表达、学习、数据、职业这些真本事，AI 只出现在练习环节（出题、追问、按判据挑错），不代写、不评分。这样即使 AI 工具换了一代，课程里的方法仍然成立。

统一形态：9–10 屏 × 40–45 秒，约 6.5–7.5 分钟；每门课统一「判据 → 同一份材料的坏/好对照 → 课后产出 → 别人能验收」。练习全部落在课后作业 + 自检表，不依赖平台交互能力。素材上：G4 的图表全部自绘 SVG（不造假截图），G5 的职业数据只用公开统计口径并在讲义标来源。

### G1 · 结构化表达与写作

- **定位**：先把结论说出来，再把理由排好，最后删掉一半。
- **受众**：写周报、方案、邮件，却总被说「看不到重点」的职场人。
- **学完能**：① 把「我做了 A、B、C」的汇报改写成 60 字结论先行的摘要；② 一个题目切出 3 个互不重叠、可验证的分论点；③ 用「删 30%、换顺序、换主语」改一稿，并说清每刀的理由。
- **场景（9 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 读者只给十秒 | 同一段话两种写法，一种被划走，一种当天被回复 |
| S02 | bluf | 结论先行 | 「我调研了 A、B、C」改成「建议 C，因为 A 和 B」 |
| S03 | pyramid | 结论、理由、事实 | 三层金字塔，上层必须被下层撑住；倒过来就是流水账 |
| S04 | mece | 切分不重不漏 | 同一题目三种切法，只有能直接落到决策的那种可用 |
| S05 | scqa | 背景、冲突、答案 | 两句背景、一句冲突、一句答案，替代从盘古开天讲起 |
| S06 | onepara | 一段一义 | 每段第一句就是结论，删掉承上启下的过渡句 |
| S07 | verb | 把动词找回来 | 「进行优化」「做出提升」还原成「改」「省 20%」 |
| S08 | revise | 改稿三刀 | 删 30%、换顺序、换主语，每刀给一个能判断的理由 |
| S09 | drill | 练什么、怎么验收 | 500 字方案 + 五问自检表；验收是同事能复述你的结论 |

- **练习/交付物**：一页 500 字方案（结论 + 3 个理由 + 1 个风险 + 1 个请求）+ 改前/改后 + 自检表。验收：只看结论句，同事能说出你要他做什么。
- **AI 陪练**：只让它按「缺结论句、分论点重叠、空话」三类挑错，不许它改写。
- **优先级**：P1（可在第二波穿插，作为「不止 AI」的信号）。

### G2 · 讲清楚一件事：演讲与授课设计

- **定位**：把「我准备了很多」变成「听众只带走一件事」。
- **受众**：要做汇报、内部分享、客户提案、面试表达的人。
- **学完能**：① 用一句话论题 + 三个支撑点写出 10 分钟骨架；② 把 40 页 deck 压到 12 页，每页只留一个论点；③ 设计 30 秒开场与 15 秒收尾，能用四步把一件事教给别人。
- **场景（10 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 只记得一件事 | 听完三场分享，你只记住一个句子或一个故事 |
| S02 | onething | 一句话论题 | 写出「听完你会_____」：一句话、有动词、可验证 |
| S03 | audience | 站到听众那边 | 他们已知什么、担心什么、听完要做什么决定 |
| S04 | three | 三个支撑点 | 每点一个证据一个例子；讲不出第三点就删一点 |
| S05 | oneslide | 一页一个论点 | 一页塞五个点的 deck 拆开后，每页都变强 |
| S06 | visual | 图替字 | 数字用柱、对比用双栏、流程用箭头；只读图就能得到结论 |
| S07 | opener | 开场三十秒 | 钩子、承诺、路线；第二句就说清你会得到什么 |
| S08 | delivery | 讲的时候 | 语速降到平时八成，句号处停一秒；忘词回到论题句 |
| S09 | rehearse | 排练与验收 | 录 90 秒开场，让一名听众复述你的核心句 |
| S10 | teachback | 讲给别人听 | 解释、示范、让对方做一次、给一次反馈，四步教一件事 |

- **练习/交付物**：12 页提纲（每页一句话论题）+ 90 秒开场录音 + 一次 5 分钟教别人的回放。验收：听众 10 秒内能复述核心句。
- **AI 陪练**：让它扮演最难搞的听众，连问三个「所以呢」；答不住的地方就是下一页要补的。
- **优先级**：P2。

### G3 · 学会学习：知识管理与刻意练习

- **定位**：学习不是收藏和重看，是提取、间隔、在难点上要反馈。
- **受众**：想学新技能却总半途而废的职场人、备考与转行者。
- **学完能**：① 用问题卡代替摘抄，把一段材料做成 5 张可自测的卡；② 说明 1/3/7/15/30 复习点的依据并排一张 30 天日程；③ 用刻意练习四件套（子技能、即时反馈、在失败线附近重复、错误日志）设计 4 周训练。
- **场景（9 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 收藏三百篇，什么也没学会 | 输入量和掌握量之间没有必然关系 |
| S02 | retrieval | 读十遍不如考一遍 | 合上书回忆一次，比重读更牢（测试效应） |
| S03 | spacing | 复习点为什么是这些 | 在快要忘的时候复习成本最低：1/3/7/15/30 |
| S04 | chunk | 组块 | 高手不是记性好，是把零散信息压成了模式 |
| S05 | deliberate | 刻意练习不是重复 | 在刚好会失败的那一档练，每轮立刻拿反馈 |
| S06 | feedback | 反馈从哪来 | 自评清单、同侪互看、录下来、错误日志，选两个 |
| S07 | project | 用输出倒逼输入 | 先定要交付的东西，再决定学什么、学到哪算够 |
| S08 | notes | 笔记最小可用版 | 问题卡 + 索引两件套；摘抄不算笔记 |
| S09 | plan | 30 天计划与验收 | 每周三次、每次 45 分钟；第 7 天不看材料答卡 |

- **练习/交付物**：5 张问题卡 + 4 周计划（12 次练习）+ 错误日志模板。验收：第 7 天不看材料答出 5 张卡，并说出错在哪。
- **AI 陪练**：让它对照材料出 5 道追问卡，只出题不给答案；答错的进错误日志。
- **优先级**：P2。

### G4 · 数据素养：看懂数字不被骗

- **定位**：每个数字背后都有分母、口径和选择；先问分母，再看坐标轴，最后问谁被漏掉了。
- **受众**：看报表、发布会和新闻的职场人，不要求统计基础。
- **学完能**：① 看到百分比先问分母与口径；② 识破截断轴、双轴、面积放大、选择性区间四种手法；③ 用均值/中位数/基率修正一个直觉判断，并区分相关与因果。
- **场景（10 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 同一个数字，两个故事 | 从 1 涨到 4，柱状像 4 倍，截断轴像几十倍 |
| S02 | denominator | 先问分母 | 百分比没有分母就是半个句子：涨 300% 是从多少到多少 |
| S03 | base-rate | 基率 | 100 人里出 1 个的新闻，和你的日常概率差几个量级 |
| S04 | axis | 坐标轴把戏 | 截断、倒置、省零点：同一组数据的三种变形 |
| S05 | dual | 双轴错觉 | 两条线相交，可能只是两个轴各自调过 |
| S06 | area | 面积与长度 | 半径放大 2 倍，面积 4 倍；气球图不能当比例图 |
| S07 | average | 均值、中位数、分布 | 平均工资上涨，可能只是最上面的人在涨 |
| S08 | selection | 谁没被统计进去 | 幸存者、中途退出、只算活跃用户 |
| S09 | causal | 相关不是因果 | 共同原因、反向因果、纯巧合，各一个反例 |
| S10 | drill | 数字体检五问 | 分母、口径、坐标、样本、谁受益，拿一条新闻走一遍 |

- **练习/交付物**：挑一条新闻里的 3 个数字填五问体检表；再做反向练习：如果我是发布方，这张图我会怎么画。验收：指出一个被误用的百分比或图表，并说清改法。
- **AI 陪练**：让它扮演发布方为一张可疑图表狡辩，你当审稿人逐条驳回。
- **优先级**：P1（可在第二波穿插）。

### G5 · AI 时代的职业地图与个人品牌

- **定位**：不预测哪个岗位消失，而是把岗位拆成任务，再决定学什么、怎么被看见。
- **受众**：工作 3–10 年、担心被替代或想换赛道的职场人。
- **学完能**：① 把本岗位拆成 10–15 件任务，分成 AI 代做、人机协作、只有人做三类；② 写出一句话定位（帮谁、解决什么问题、凭什么是我）和三个可展示案例；③ 排一张 30 天计划：学一个可验证技能、发三条作品、约三次求助。
- **场景（10 屏）**：

| S | id | 标题 | 大意 |
| --- | --- | --- | --- |
| S01 | hook | 消失的是任务，不是职业 | 同一个岗位被打散，十几件任务各自命运不同 |
| S02 | inventory | 把一天拆成任务 | 写 10–15 件具体任务，动词开头，不写岗位名 |
| S03 | buckets | 三类任务 | AI 代做、人机协作、只有人做，每类标一条证据 |
| S04 | judgment | 判断力资产 | 经验、关系、品味、担责，四项里你最厚的是哪项 |
| S05 | positioning | 一句话定位 | 我帮谁、解决什么问题、凭什么是我 |
| S06 | proof | 作品胜过简历 | 三个案例：问题、动作、带数字的结果 |
| S07 | visibility | 被看见 | 写、讲、做选一条主渠道做 90 天，别三条一起 |
| S08 | network | 机会从哪来 | 弱连接与求助：给具体的人一个具体的小请求 |
| S09 | plan | 30 天 | 一个技能 + 三条作品 + 三次求助，每周检查 |
| S10 | closing | 职业是组合，不是阶梯 | 技能、作品、关系三条线各自复利 |

- **练习/交付物**：任务三分类表 + 一句话定位 + 30 天三条选题。验收：同行看完能复述你的定位，并指出你分类错的一项。
- **AI 陪练**：让它按你的任务清单生成三类任务初稿，你逐条改错并补证据。
- **优先级**：P2（职业数据需要年度维护）。

## 9. 交互式课堂怎么设计

### 9.1 一门旁白小课的标准结构

第一课是 28 屏的长视频；后续旁白小课建议统一成「1 + 2 + 4 + 1 + 1」的结构：

| 段落 | 屏数 | 做什么 | 时长 |
| --- | --- | --- | --- |
| 钩子 | 1 | 一个真实痛点或翻车现场，不铺垫 | 30–45s |
| 概念 | 2–3 | 每屏一个必要概念，配一个可视比喻 | 每屏 40–60s |
| 演示 | 3–5 | 真实软件画面 / 代码 / 终端，before → after，每屏一个动作 | 每屏 50–70s |
| 翻车 | 1 | 常见错误与代价，给检查点 | 45s |
| 行动 | 1 | 清单、模板、下一步；和下一门课衔接 | 45s |

总 8–12 屏、5–9 分钟。每屏仍然只讲一个论题，一屏讲不完就拆屏。

### 9.2 练习与验收：按平台能力分三档

| 档位 | 能做什么 | 平台改动 | 什么时候用 |
| --- | --- | --- | --- |
| A 轻量 | 课末「行动卡」写进讲义与字幕；课后任务、模板、检查清单以讲义文字给到；练习文件随课程包 `composition/assets/` 静态直链分发 | 无 | P0 全部课程 |
| B 中等 | 随堂练习屏（单选/多选/排序/拖拽）；课程页「资料区」入口；代码块一键复制 | 课程契约 v2（`interactive: true` 落地）+ 课程页资料区 | P1 应用课 |
| C 完整 | 内置代码/网页预览沙箱、作品提交与互评、系列学习路径、打卡与证书 | 平台大版本 | P2 之后 |

注意：**练习资料下载不用等平台**。课程包里的 `composition/assets/` 会随构建整体复制进 `dist/`，先放文件、在讲义里给路径即可；课程页加资料区是体验增强，不是前置条件。

建议路径：先用 A 把内容跑起来，用数据和反馈判断哪些课值得投 B；C 等系列课成型后再做。不要为了「交互」先做平台，最后课程内容反而没时间打磨。

### 9.3 系列怎么组织（当前没有系列页）

现在站点只有课程库与单课页，没有「学习路径」页。过渡方案：

1. 用 `course.json` 的 `tags` 与 `order` 把同系列课排在相邻位置。
2. 每门课封面写清「先修 / 下一课」，课程第一屏和最后一屏各留一句衔接。
3. 在课程库用 tag 过滤当作「系列」入口（如 `AI 基础`、`办公提效`、`AI 编程`）。

平台任务（建议排进下一阶段）：`course.json` 增加 `series` 字段 + `/paths/<slug>` 聚合页 + 路径进度图。

### 9.4 课堂运营

- **课程负责讲清楚，直播负责看你的东西。** 每个系列配一次直播答疑/作业点评，比多录十节课更有黏性。
- **每门课一个可检查的产出。** 没有产出就只是「看过」，产出是达人的证据。
- **版本化。** 工具类课程标注「最后复核日期」，过时先改文案与画面，再重录旁白（旁白缓存按文本指纹失效，改文案会自动重生成）。

## 10. 制作顺序与波次

### 10.1 三波建设

| 波次 | 建议周期 | 课程 | 为什么先做这些 |
| --- | --- | --- | --- |
| 第一波 P0（8 门） | 10–12 周 | F1 提示词、F3 判断力、O1 PPT、O2 文档、O3 表格、W1 第一个网页、D1 AI 编程入门、D2 需求与计划 | 地基 + 两条路线入口；办公三件套负责拉新，编程入口负责立口碑，一次验证两类受众 |
| 第二波 P1（12 门） | 12–16 周 | F2 模型与工具、F4 工作区记忆、O4 调研、W2 交互网页、W3 小工具、A2 个人 Agent、D3 调试、D4 测试与评审、D6 项目记忆进阶、D9 安全底线、G1 结构化写作、G4 数据素养 | 把两条路线补成能独立干活的完整工作流；安全底线尽早；穿插两门非 AI 课，验证「不止 AI」的定位 |
| 第三波 P2（14 门） | 按季度滚动 | O5 内容创作、A1 工作流、W4 产品课、D5 重构、D7 Skill 与 MCP、D8 多 Agent、D10 AI 应用架构、D11 团队落地、X1–X3、G2、G3、G5 | 进阶、达人项目课与通识线；等练习能力与系列页就位后做效果更好 |

### 10.2 每波的验收

- **内容**：每门课按[课程契约](../docs/course-contract.md)第 8 节验收（旁白小课按 3.4 的新档位补一条）；事实有来源；有一句话论题、有一个可交付物。
- **故事板先审**：同一波内一次审 3 门 storyboard，通过后再做动画，减少返工。
- **平台**：P0 开工前必须先完成旁白流水线参数化（见 10.3 第 1 条），否则第二门旁白课无法开工；P1 开工前决定练习屏与资料区；P2 开工前完成系列页立项。
- **数据**：每波结束看两个数：完播率、课后产出提交率（没有提交就先人工收集）。

### 10.3 平台前置任务（建议排期）

| 优先级 | 任务 | 原因 |
| --- | --- | --- |
| P0（P0 课程开工前） | 课程契约修订：补「旁白小课」档 + 修掉 3.4 列出的文档矛盾 | 形态不定义，storyboard 的屏数与时长没有验收依据 |
| P0（第二门课之前） | 旁白流水线参数化（`build_narration.py` / `curate_narration.py` / `prepare_course_media.py` 写死 `ai-first-sees`） | 不参数化，任何第二门旁白课都做不了 |
| P0（第二门课之后） | CI 质量门：check / snapshot / axe / 独立部署 / 预算 | 30 门课靠人工验收必漏 |
| P1 | 课程页「资料区」入口（文件已经在课程包里，只差入口） | 练习模板与检查单更好用 |
| P1 | 练习屏契约 v2：单选、多选、排序；可跳过、可回看 | 应用课想从「看懂」变「练会」 |
| P1 | `series` 字段 + 系列聚合页 + 路径进度 | 34 门课没有路径会迷路 |
| P2 | 课程版本与复核日期展示（`credits.updatedAt` 已有） | 工具类课程需要「最后复核」 |
| P2 | 视频批量导出队列（现在是单任务） | 课程多了会排队 |
| P3 | 作品提交/打卡/证书、搜索、多语言、竖屏 composition | 运营与规模化的下一步 |

### 10.4 内容生产节奏

- 每门旁白小课 1–2 周（1 人 + AI 辅助：写 storyboard → 做 scene → 旁白合成 → 构建验收）。
- 每波 10–16 周，波内按「基础 → 路线入口 → 路线进阶」排序；34 门课整体约 12–18 个月，不要指望一个季度铺完。
- 长视频旗舰课（30 分钟级）建议一年 1 门，用来建立品牌；其余都做旁白小课。

## 11. 事实、时效与更新机制

- **内容分三类管理时效**：
  - 概念（上下文、Agent、评测）：1–2 年有效，讲清楚即可。
  - 工作流（提示词、协作方式、调试）：6–12 个月。
  - 工具与产品（入口、菜单、型号、价格、榜单）：1–3 个月，**尽量少上屏**。
- **每门课的元数据**写 `credits.updatedAt`，课程内首屏或末屏标注「最后复核：YYYY-MM」。
- **事实来源**：官方文档、发布说明、论文优先；截图只用真实界面；禁止 AI 生成假界面。第一课已经建立的口径继续沿用（截至 2026-11-12）。
- **失效处理顺序**：改文案与截图 → 重录旁白 → 重建课程。旁白缓存按 voice + rate + 文本指纹失效，改文案会触发重新合成。
- **季度体检**：每季度列一次过期清单，标出「必须改」「可以等」「直接下架」。

## 12. 待确认的问题

1. **形态确认**：是否同意在课程契约里补一档「旁白小课」（8–12 屏 / 5–10 分钟，见 3.4）？这是全部后续课开工的前提。
2. **第一波做几门？** 本文建议 P0 八门；如果想更稳，先做 F1 + F3 + O1 + W1 + D1 五门，也能验证两条路线。
3. **两条路线谁优先？** 建议 P0 并行：办公三件套拉新，编程入口立口碑；如果资源只够一条线，先做非编程（需求更广）。
4. **要不要做练习屏与作品提交？** 决定平台任务的优先级；建议先用「行动卡 + 课后作业 + 静态资料包」过渡，跑一两波再决定。
5. **通用能力线**：G1 / G4 放第二波穿插是否同意？还是等 AI 主线铺完再做？
6. **配套运营**：每个系列是否配直播答疑/作业点评？谁出镜、谁配音、更新频率多少？
7. **长视频旗舰**：是否保留一年 1 门 30 分钟长视频？
